Gated Recurrent Unit – Hyperparameters

Master every dial and knob that shapes GRU performance

A Gated Recurrent Unit (GRU) is a streamlined RNN variant designed to combat the vanishing gradient problem. Its real‑world success hinges on choosing the right hyperparameters. This guide covers all 10 essential ones — from hidden units to loss functions — with practical Keras examples and a ready‑to‑run stock market prediction demo.

🔬 GRU Cell Architecture
Update Gatezt = σ(Wzxt + Uzht-1)
Controls how much past to keep
⟶
Reset Gatert = σ(Wrxt + Urht-1)
Controls how much past to forget
⟶
Hidden Stateht = (1−zt)⊙ht-1 + zt⊙h̃t
Blends old & new information
σ = sigmoid  |  ⊙ = element‑wise multiplication  |  2 gates (vs LSTM's 3)

🧩

① Number of GRU Units (Hidden Units)

Defines how many neurons exist in the GRU layer. More units = higher capacity to learn complex patterns, but also more memory and risk of overfitting.

from tensorflow.keras.layers import GRU
GRU(128) # 128 hidden units
💡Start with 64 or 128. Double only if underfitting persists.
⚠️Too many units (≥512) on small datasets → severe overfitting.
🏢

② Number of Layers

Stack multiple GRU layers for deeper feature extraction. Use return_sequences=True on all but the last GRU layer.

model.add(GRU(128, return_sequences=True))
model.add(GRU(64)) # final GRU layer
✅1–3 layers usually suffice. More layers = more training time.
🎯

③ Learning Rate

Controls the step size during weight updates. The single most impactful hyperparameter.

from tensorflow.keras.optimizers import Adam
optimizer = Adam(learning_rate=0.001)
💡0.001 (Adam default) is a great starting point for most problems.
⚠️Too high (≥0.1) → loss explodes. Too low (≤1e-5) → painfully slow convergence.
📦

④ Batch Size

Number of samples processed before each weight update. Balances gradient stability and training speed.

model.fit(X_train, y_train, batch_size=32)
💡32 is a safe default. Use 16 for noisy gradients, 64–128 for speed on large datasets.
🔄

⑤ Number of Epochs

How many complete passes through the training dataset. Use Early Stopping to avoid overfitting.

model.fit(X_train, y_train, epochs=50)
✅Always pair with EarlyStopping callback — let the model decide when to stop.
🎲

⑥ Dropout & Recurrent Dropout

Randomly drops connections during training to prevent overfitting. GRU supports both input dropout and recurrent dropout.

GRU(128, dropout=0.2, recurrent_dropout=0.2)
💡Typical range: 0.1–0.5. Start with 0.2 and increase if overfitting.
📏

⑦ Sequence Length (Time Steps)

Number of previous time steps fed into the model. Directly shapes the input tensor.

# Predict stock price using last 30 days
time_steps = 30
input_shape = (30, 5) # 30 days, 5 features
⚠️Too long → vanishing gradients return. Too short → misses long‑term patterns.
⚡

⑧ Activation Function

GRU internally uses tanh (candidate state) and sigmoid (gates). You can specify the output activation.

GRU(128, activation='tanh')
✅Default tanh works well. Rarely needs changing for standard GRU cells.
🔧

⑨ Optimizer

Controls the weight update strategy. Adam is the go‑to choice for most GRU applications.

model.compile(optimizer='adam', loss='mse')
# or: optimizer='rmsprop' | 'sgd'
💡Adam ≈ adaptive learning rate + momentum. Best default for GRU models.
📉

⑩ Loss Function

Measures prediction error. Choice depends entirely on problem type.

# Regression
model.compile(loss='mse')
# Classification
model.compile(loss='categorical_crossentropy')
💡MSE for regression, Binary/Categorical Crossentropy for classification.

🏗️ GRU Architecture & Structure

The GRU cell uses two gates (update & reset) instead of LSTM's three, making it computationally lighter while retaining the ability to capture long‑range dependencies.

🔬 GRU Core Equations
Update Gate:
zt = σ(Wz·xt + Uz·ht−1)
Reset Gate:
rt = σ(Wr·xt + Ur·ht−1)
Candidate State:
h̃t = tanh(W·xt + U·(rt⊙ht−1))
Final Hidden State:
ht = (1−zt)⊙ht−1 + zt⊙h̃t

📖 Equation Element Breakdown – What every symbol means

Let’s dissect each component of the update gate equation zt = σ(Wz·xt + Uz·ht−1) and the other GRU equations. Understanding the role of each tensor helps you see why GRUs work.

🔹 Update Gate: zt = σ(Wzxt + Uzht−1)
σ (sigmoid)
The logistic function, outputs values between 0 and 1. Acts as a soft switch: 0 = “keep nothing”, 1 = “keep everything”.
Output: (0,1) per element
Wz
Weight matrix applied to the current input xt. Learned during training. Determines how current input influences the update decision.
Shape: (hidden_units, input_features)
xt
The input vector at time step t (e.g., today’s stock features). This is the new information arriving at the cell.
Shape: (batch_size, input_features)
Uz
Weight matrix for the previous hidden state ht−1. Governs how much the past memory affects the update gate.
Shape: (hidden_units, hidden_units)
ht−1
Hidden state from the previous time step. The cell’s “memory” before seeing xt. Carries information from earlier time steps.
Shape: (batch_size, hidden_units)
zt
Update gate output – a vector of values in (0,1). Later used to blend old hidden state and new candidate state. High zt → keep more new info; low zt → retain old memory.
Shape: (batch_size, hidden_units)
🔹 Reset Gate: rt = σ(Wrxt + Urht−1)
Wr, Ur
Similar to Wz, Uz but specialised for the reset gate. They learn to decide how much of the past to forget when computing the candidate state.
Wr: (hidden_units, input_features), Ur: (hidden_units, hidden_units)
rt
Reset gate vector (values in 0–1). When rt is near 0, the cell “forgets” the previous state and treats xt as the start of a new sequence.
Shape: (batch_size, hidden_units)
🔹 Candidate Hidden State: h̃t = tanh( W xt + U (rt ⊙ ht−1) )
tanh
Hyperbolic tangent function, outputs between -1 and 1. Normalizes the candidate state so it can both increase and decrease the hidden values.
Output: (-1,1) per element
W, U
Weight matrices for the candidate state computation. U interacts with the reset‑gated previous hidden state, allowing the cell to ignore irrelevant history.
W: (hidden_units, input_features), U: (hidden_units, hidden_units)
⊙ (element‑wise multiplication)
The Hadamard product: multiplies corresponding elements of two vectors. In rt ⊙ ht−1, it zeros out parts of the previous hidden state that the reset gate deems irrelevant.
Output shape matches inputs
h̃t
Candidate hidden state – a proposed new memory content based on current input and selectively remembered past. It is not the final state; it will be blended with the old state via the update gate.
Shape: (batch_size, hidden_units)
🔹 Final Hidden State: ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t
(1 − zt) ⊙ ht−1
Keeps a fraction of the old hidden state. Where zt is close to 0, we retain almost all of the previous memory.
Same as ht−1
zt ⊙ h̃t
Adds a fraction of the new candidate state. Where zt is high, the new proposal dominates.
Same as h̃t
ht
The final hidden state at time t – a linear interpolation (convex combination) between old memory and new candidate. This becomes the output and the memory for the next time step.
Shape: (batch_size, hidden_units)
💡 Key insight: Because zt is a vector (not a single number), the GRU can decide independently for each feature whether to keep the old value or update it. This adaptive gating is what makes GRUs so effective for sequences.
🔍

Update Gate (zt)

Decides how much of the past hidden state to carry forward. Values near 1 retain old info; near 0 replace it with new info.

💡This is the key innovation — one gate handles both "forget" and "input" decisions.
🔄

Reset Gate (rt)

Controls how much of the previous hidden state contributes to the candidate state. Allows the cell to discard irrelevant history.

💡When rt ≈ 0, the cell behaves as if reading the first symbol of a new sequence.

⚡ Training Process Hyperparameters

These hyperparameters govern how the model learns — controlling the optimization trajectory, convergence speed, and data flow during training.

🎯

Learning Rate

The step size for gradient descent. Arguably the most critical hyperparameter to tune.

Adam(learning_rate=0.001)
✅Use learning rate scheduling (e.g., ReduceLROnPlateau) for automatic adjustment during training.
📦

Batch Size

Affects gradient noise and training speed. Small batches → better generalization; large batches → faster but riskier.

model.fit(X, y, batch_size=32)
🔄

Epochs

Full dataset passes. More isn't always better — monitor validation loss.

model.fit(X, y, epochs=50)
⚠️Without EarlyStopping, too many epochs → memorization of training data.
🔧

Optimizer Choice

Adam adapts learning rates per‑parameter; RMSprop handles non‑stationary objectives well; SGD with momentum is a classic.

# Adam: best default
model.compile(optimizer='adam')
# RMSprop: good for RNNs
model.compile(optimizer='rmsprop')

🛡️ Regularization & Tuning

Prevent overfitting and improve generalization with these techniques specifically designed for recurrent networks.

🎲

Dropout (Input)

Randomly zeros input units during training. Applied to the input connections of the GRU cell.

GRU(128, dropout=0.3)
💡0.2–0.3 is a safe starting range for most sequence models.
🔁

Recurrent Dropout

Applies dropout to the recurrent connections (hidden‑to‑hidden). More aggressive regularization.

GRU(128, recurrent_dropout=0.2)
⚠️Too high (≥0.5) can destroy the cell's ability to maintain long‑term memory.
⏳

Early Stopping

Halts training when validation loss stops improving. Essential for preventing overfitting.

from tensorflow.keras.callbacks import EarlyStopping
EarlyStopping(monitor='val_loss', patience=10)
📉

Learning Rate Scheduling

Gradually reduces the learning rate as training plateaus, helping the model settle into a better minimum.

from tensorflow.keras.callbacks import ReduceLROnPlateau
ReduceLROnPlateau(factor=0.5, patience=5)

💻 Full Code – Stock Market Prediction with GRU

A complete, runnable example using synthetic stock‑like data. Every hyperparameter is annotated with circled numbers (①–⑩) matching the cards above.

#!/usr/bin/env python3 """GRU Stock Market Prediction – All Hyperparameters Demonstrated""" import numpy as np import matplotlib.pyplot as plt from sklearn.preprocessing import MinMaxScaler from sklearn.model_selection import train_test_split from tensorflow.keras.models import Sequential from tensorflow.keras.layers import GRU, Dense, Dropout from tensorflow.keras.optimizers import Adam from tensorflow.keras.callbacks import EarlyStopping, ReduceLROnPlateau # ── Generate Synthetic Stock Data ── np.random.seed(42) n_samples = 2000 t = np.arange(n_samples) trend = 0.05 * t seasonality = 15 * np.sin(2 * np.pi * t / 250) noise = np.random.normal(0, 3, n_samples) price = 100 + trend + seasonality + noise price = np.maximum(price, 10) # no negative prices # ── Feature Engineering ── returns = np.diff(price, prepend=price[0]) / (price + 1e-8) ma_10 = np.convolve(price, np.ones(10)/10, mode='same') ma_30 = np.convolve(price, np.ones(30)/30, mode='same') volatility = np.array([np.std(price[max(0,i-10):i+1]) for i in range(n_samples)]) features = np.column_stack([price, returns, ma_10, ma_30, volatility]) scaler = MinMaxScaler() features_scaled = scaler.fit_transform(features) # ── ⑦ SEQUENCE LENGTH / TIME STEPS ── TIME_STEPS = 30 # ⑦ Lookback window: 30 days N_FEATURES = features_scaled.shape[1] # 5 features def create_sequences(data, target_idx=0, time_steps=TIME_STEPS): X, y = [], [] for i in range(len(data) - time_steps): X.append(data[i:i+time_steps]) y.append(data[i+time_steps, target_idx]) return np.array(X), np.array(y) X, y = create_sequences(features_scaled) X_train, X_test, y_train, y_test = train_test_split( X, y, test_size=0.2, shuffle=False ) # ── Build GRU Model ── model = Sequential() # ① Number of Units: 128 | ⑥ Dropout: 0.2 | ⑧ Activation: tanh model.add(GRU( units=128, # ① Hidden units dropout=0.2, # ⑥ Input dropout recurrent_dropout=0.2, # ⑥ Recurrent dropout activation='tanh', # ⑧ Activation function return_sequences=True, # ② Needed for stacking input_shape=(TIME_STEPS, N_FEATURES) # ⑦ Shape from sequence length )) # ② Second GRU layer (fewer units) model.add(GRU( units=64, # ① Fewer units in deeper layer dropout=0.2, # ⑥ recurrent_dropout=0.2, # ⑥ return_sequences=False # ② Final GRU: no sequences returned )) # Output layer for regression model.add(Dense(1)) # Single value: predicted price # ── ⑨ OPTIMIZER & ③ LEARNING RATE & ⑩ LOSS ── optimizer = Adam(learning_rate=0.001) # ⑨ Adam optimizer | ③ LR = 0.001 model.compile( optimizer=optimizer, # ⑨ loss='mse' # ⑩ MSE for regression ) model.summary() # ── Callbacks ── early_stop = EarlyStopping( monitor='val_loss', patience=15, restore_best_weights=True ) reduce_lr = ReduceLROnPlateau( monitor='val_loss', factor=0.5, patience=5, min_lr=1e-6 ) # ── ④ BATCH SIZE & ⑤ EPOCHS ── history = model.fit( X_train, y_train, batch_size=32, # ④ Batch size epochs=100, # ⑤ Epochs (with early stopping) validation_split=0.15, callbacks=[early_stop, reduce_lr], verbose=1 ) # ── Evaluate ── test_loss = model.evaluate(X_test, y_test, verbose=0) print(f"📊 Test MSE: {test_loss:.6f}") # ── Predict ── predictions = model.predict(X_test) # ── Plot ── plt.figure(figsize=(14, 5)) plt.plot(y_test[:200], label='Actual', alpha=0.8) plt.plot(predictions[:200], label='Predicted', alpha=0.8) plt.title('GRU Stock Price Prediction (First 200 Test Samples)') plt.legend() plt.tight_layout() plt.savefig('gru_stock_prediction.png', dpi=150) plt.show() print("✅ Done! Check 'gru_stock_prediction.png'")
