1 Algorithm Description

Real-life analogy: Imagine you're a financial advisor recommending stocks to a client. A naive advisor might say "put 80% in this one stock — it had the best returns last year." That's risky — one stock's noise got over-weighted. A wise advisor would say "let's diversify; no single stock gets more than 15% of the portfolio, even if it looks amazing." Ridge Regression does exactly this with feature coefficients: it puts a "leash" on any coefficient that tries to grow too large, keeping the model diverse and stable.

What is Ridge Regression?

Ridge Regression (also called Tikhonov Regularisation or L2 Regularisation) is a variant of linear regression that adds a penalty proportional to the sum of squared coefficients to the cost function. This penalty shrinks coefficients toward zero but never exactly to zero, keeping all features in the model with reduced influence.

It solves two major problems of Ordinary Least Squares (OLS):

  • Multicollinearity — when features are highly correlated, OLS coefficients become unstable (huge variance). Ridge stabilises them.
  • Overfitting — when there are many features relative to samples (p > N or p ≈ N), OLS overfits. Ridge trades a small increase in bias for a large reduction in variance.

The Core Idea in Three Sentences

1. Fit a linear model, but add a penalty for large coefficients: Cost = SSE + λ·Σβⱼ².

2. The penalty λ controls the trade-off: λ = 0 → OLS; λ = ∞ → all coefficients = 0; λ in between → shrunk coefficients.

3. Choose λ by cross-validation to minimise out-of-sample error.

How the Algorithm Learns (Step by Step)

Step 1 — Standardise features

Ridge is sensitive to feature scale because the penalty treats all coefficients equally. Centre each feature to mean 0 and scale to standard deviation 1. Also centre the target y so the intercept β₀ is the mean of y and does not get penalised.

Step 2 — State the penalised cost function

J(β) = Σi=1N ( yi − β0 − Σj=1p βjxij )² + λ · Σj=1p βj²

Note: the intercept β₀ is not penalised. Only the slope coefficients β₁…βₚ are penalised.

Step 3 — Solve via closed form or gradient descent

For moderate p, use the closed form:

β̂Ridge = (XᵀX + λI)−1 Xᵀy

For very large p or streaming data, use gradient descent with the modified gradient:

∂J/∂βj = −2 · Σ xij(yi − ŷi) + 2λβj

Step 4 — Choose λ by cross-validation

λ is a hyperparameter — not learned from training data. Use K-fold cross-validation to find the λ that minimises out-of-sample error. The standard approach is to plot validation error vs. log(λ) and pick the minimum (the "1-SE rule" picks the largest λ within one standard error of the minimum, favouring sparser models).

Step 5 — Refit and evaluate

Refit the model with the chosen λ on the full training set, then evaluate on a held-out test set or via cross-validation.

2 Applications

Ridge Regression shines whenever you have many correlated features, few samples relative to features, or noisy data — which describes most real-world problems.

🧬 Genomics & Bioinformatics

  • GWAS (Genome-Wide Association Studies) — thousands of SNPs, highly correlated.
  • Gene expression prediction — p ≫ N (more genes than samples).
  • Polygenic risk scores — thousands of variants, small effects.
  • Proteomics — high-dimensional protein abundance data.

💰 Finance & Economics

  • Portfolio optimisation — correlated asset returns (Markowitz).
  • Factor models — Fama-French factors with collinearity.
  • Credit risk modelling — many correlated financial ratios.
  • Interest rate curve fitting — Nelson-Siegel with shrinkage.
  • Volatility forecasting — HAR model with Ridge penalty.

🏥 Healthcare & Epidemiology

  • Disease risk prediction — many clinical covariates.
  • Medical imaging — radiomics features (many, correlated).
  • Drug response — high-dimensional patient profiles.
  • Hospital length of stay — with correlated diagnoses.

📈 Marketing & Business

  • Marketing mix modelling — media channels correlate with each other.
  • Customer lifetime value — many behavioural features.
  • Sales forecasting — correlated economic indicators.
  • Pricing models — hedonic regression with correlated attributes.

🏭 Engineering & Science

  • Sensor calibration — many correlated sensor readings.
  • Chemometrics — spectroscopy (thousands of wavelengths).
  • Materials science — property prediction from many descriptors.
  • Signal processing — Ridge used in regularised least squares.

🌐 Technology & ML Foundations

  • Recommender systems — Ridge for collaborative filtering.
  • Time-series forecasting — regularised autoregression (Ridge VAR).
  • Neural network regularisation — weight decay is L2 regularisation.
  • Kernel Ridge Regression — nonlinear extension via kernels.
  • Baseline for high-dim data — always compare against Ridge.
When is Ridge the right tool? If your data has many features, some of which are correlated, and you suspect OLS is overfitting or producing unstable coefficients, Ridge is almost always a good starting point. It's the default regularised linear model — the linear regression everyone should try before moving to more complex models.

3 Advantages

  • Handles multicollinearity elegantly — when features are highly correlated, OLS coefficients become unstable. Ridge shrinks them toward zero, stabilising the model.
  • Works when p > N — when there are more features than samples, OLS has infinitely many solutions. Ridge has a unique solution thanks to the λI term.
  • Reduces variance dramatically — the whole point. Ridge trades a small increase in bias for a large reduction in variance, often improving out-of-sample predictions.
  • Closed-form solution — no iterative optimisation needed. β̂ = (XᵀX + λI)⁻¹Xᵀy is a single matrix inversion.
  • Very fast to train and predict — a matrix inversion is O(p³), but for typical p it's milliseconds.
  • Tiny memory footprint — you store only p+1 coefficients.
  • Extremely interpretable — coefficients still have meaning: how much y changes per unit xⱼ, with all other features held fixed.
  • Numerically stable — the λI term improves the condition number of XᵀX, making inversion reliable.
  • Well-founded theory — Ridge is the maximum a posteriori (MAP) estimate under a Gaussian prior on coefficients, giving it a Bayesian interpretation.
  • One hyperparameter — only λ needs tuning. Everything else is OLS.
  • Foundation for more advanced models — Kernel Ridge, Ridge for collaborative filtering, weight decay in neural nets, ridge-regularised GLMs.
  • No feature selection bias — unlike Lasso, Ridge keeps all features, which is preferred when all features have some signal (common in genomics).
  • Handles noisy data robustly — the penalty protects against fitting noise.

4 Disadvantages

  • Never produces zero coefficients — Ridge shrinks coefficients but keeps all features in the model. If you want feature selection, use Lasso or Elastic Net.
  • Every feature must be included at inference — this matters in production where fewer features mean faster serving, less data collection cost, and easier maintenance.
  • Requires standardisation — because the penalty treats all coefficients equally, features must be on the same scale. Otherwise the penalty unfairly favours small-scale features.
  • Intercept handling is subtle — the intercept is not penalised, so you must centre y or exclude β₀ from the penalty. Mistakes here produce wrong results.
  • λ must be tuned by cross-validation — extra computation. Poor λ gives you either overfitting (small λ) or oversmoothing (large λ).
  • Introduces bias — by construction. If you only care about unbiased coefficients for causal inference, Ridge is inappropriate.
  • No p-values or confidence intervals directly — because the estimator is biased, standard OLS inference doesn't apply. You need bootstrap or Bayesian methods.
  • Cannot represent sparsity — if the true model has only 5 informative features out of 1000, Ridge will give small but non-zero weights to the 995 irrelevant ones.
  • Sensitive to λ on the wrong scale — because λ scales with N and feature variance, it must be re-tuned if you change sample size or standardisation.
  • Doesn't automatically handle nonlinearity — you still need to add polynomial or interaction features manually.
  • Assumes linearity — inherits all the linear-regression assumptions: linear relationship, independence, and (for inference) normally distributed errors.
  • Sensitive to outliers — squared error loss means outliers can dominate. Use Huber-Ridge or quantile-Ridge for robustness.
  • No interaction selection — if X₁×X₂ matters, you must add it manually; Ridge won't discover it.
The sparsity trap: If your dataset has 10,000 features but only 20 are truly predictive, Ridge will give all 10,000 features a small non-zero weight. The model will still predict reasonably, but you won't know which 20 features actually matter. Use Lasso or Elastic Net when you need a sparse, interpretable model.

5 Pre-Deployment KPIs — Detailed with Formulas

These are measured before the model goes live, using a held-out test set or cross-validation. They answer: "Is this model good enough to ship?"

5.1 Regression Accuracy KPIs

MAE (Mean Absolute Error) Regression

What it measures: The average size of the prediction error, in the same units as the target. Robust to outliers because it doesn't square errors.

Formula MAE = (1/N) · Σi=1N | yi − ŷi |
Worked example: Actual = [100, 200, 300], Predicted = [110, 190, 320]
Errors = |−10|, |10|, |−20| = 10, 10, 20
MAE = (10 + 10 + 20) / 3 = 13.33
Interpretation: On average, the prediction is off by 13.33 units. Easy to explain to stakeholders.
✔ Use when You want an easy-to-explain metric and all errors have equal importance.
✘ Avoid when Large errors are dramatically worse than small ones (use RMSE).

MSE (Mean Squared Error) Regression

What it measures: The average of squared errors. This is the loss function Ridge Regression minimises (plus the penalty term).

Formula MSE = (1/N) · Σi=1N ( yi − ŷi )²
Worked example: Errors = [−10, 10, −20]
MSE = (100 + 100 + 400) / 3 = 200
Interpretation: MSE is in squared units (₹², °C²), so it's hard to interpret directly. It's used as the loss function during training.

RMSE (Root Mean Squared Error) Regression

What it measures: The square root of MSE, bringing the metric back to the original units of the target. Penalises large errors more than MAE.

Formula RMSE = √[ (1/N) · Σi=1N ( yi − ŷi )² ]
Worked example: MSE = 200
RMSE = √200 = 14.14
Interpretation: RMSE ≥ MAE always. The ratio RMSE/MAE ≈ 1.25 suggests roughly Gaussian residuals.
✔ Use when Large errors are genuinely worse (e.g. financial forecasting, demand planning).
✘ Avoid when The target has outliers you don't care about — use MAE.

R² (Coefficient of Determination) Regression

What it measures: The proportion of the target's variance that the model explains. Compares against the naive "always predict the mean" baseline.

Formula R² = 1 − ( SSres / SStot )

SSres = Σ ( yi − ŷi )²   (residual sum of squares)
SStot = Σ ( yi − ȳ )²   (total sum of squares)
Worked example: y = [100, 200, 300], ŷ = [110, 190, 320], ȳ = 200
SSres = 600, SStot = 20,000
R² = 1 − (600 / 20,000) = 0.97
Interpretation: R² = 1 → perfect; R² = 0 → no better than predicting the mean; R² < 0 → worse than the mean.
✔ Use when You want a scale-free measure of how well the model fits.
✘ Avoid when Comparing models with different numbers of features — R² always increases with more features. Use Adjusted R².

Adjusted R² Regression

What it measures: R² penalised for the number of predictors. Only increases if a new feature adds more explanatory power than would be expected by chance.

Formula Adjusted R² = 1 − [ (1 − R²) · (N − 1) ] / (N − p − 1)

N = number of samples  |  p = number of predictors
Worked example: R² = 0.97, N = 100, p = 5
Adjusted R² = 1 − [(1 − 0.97) · 99] / 94 = 1 − 2.97/94 = 0.968

MAPE (Mean Absolute Percentage Error) Regression

What it measures: The average error expressed as a percentage of the actual value. Very intuitive for business reporting.

Formula MAPE = (100% / N) · Σi=1N | ( yi − ŷi ) / yi |
Worked example: y = [100, 200, 300], ŷ = [110, 190, 320]
Errors % = 0.10, 0.05, 0.0667
MAPE = (0.10 + 0.05 + 0.0667) / 3 × 100 = 7.22%
Interpretation: On average, predictions are off by 7.22%. Range 0% to ∞ (lower is better).
✔ Use when Reporting to business stakeholders and actual values are well above zero.
✘ Avoid when Actual values can be zero or near-zero — MAPE explodes to infinity.

SMAPE (Symmetric Mean Absolute Percentage Error) Regression

Formula SMAPE = (100% / N) · Σi=1N | yi − ŷi | / [ (|yi| + |ŷi|) / 2 ]
Interpretation: Range 0% to 200% (lower is better). Handles zero values better than MAPE.

MSLE (Mean Squared Logarithmic Error) Regression

Formula MSLE = (1/N) · Σi=1N ( log(1 + yi) − log(1 + ŷi) )²
✔ Use when The target spans several orders of magnitude (e.g. revenue, population counts).

5.2 Ridge-Specific KPIs

λ (Lambda) — Regularisation Strength Ridge-Specific

What it measures: The weight of the L2 penalty. Controls the bias-variance trade-off. Larger λ = more shrinkage = higher bias, lower variance.

Range λ ∈ [0, ∞)

Special cases λ = 0 → OLS (no penalty)
λ → ∞ → all βj → 0 (only intercept remains)

Selection method K-fold cross-validation: choose λ that minimises validation error.
"1-SE rule": pick the largest λ within 1 SE of the minimum (more shrinkage, better generalisation).
Interpretation: Typical λ values range from 0.001 to 1000, depending on feature scaling and sample size. Always standardise features first.

L2 Norm of Coefficients ||β||₂² Ridge-Specific

What it measures: The total magnitude of the coefficients. Smaller = more shrinkage.

Formula ||β||₂² = Σj=1p βj²

Effect of λ As λ increases, ||β||₂² monotonically decreases.
Interpretation: Track this across λ values to see how aggressively Ridge is shrinking.

Effective Degrees of Freedom (df) Ridge-Specific

What it measures: The effective number of parameters used by the model. Ridge reduces this below p.

Formula df(λ) = trace( X(XᵀX + λI)−1Xᵀ )

Interpretation df(λ) ≤ p. As λ increases, df decreases toward 0.
At λ = 0, df = p (full OLS).
Interpretation: Effective df is used in AIC/BIC for Ridge and shows how much complexity the model is using.

Condition Number of XᵀX + λI Ridge-Specific

What it measures: How numerically stable the matrix inversion is. Ridge improves it dramatically.

Formula κ(A) = σmax / σmin   (ratio of largest to smallest singular value)

Effect of λ κ(XᵀX + λI) = (σmax² + λ) / (σmin² + λ) < κ(XᵀX)
λ small → κ close to OLS (could be huge)
λ large → κ close to 1 (perfectly stable)
Interpretation: A condition number above 10³ makes OLS unstable. Ridge reduces it, making solutions reliable.

Coefficient Stability (Across Bootstraps) Ridge-Specific

What it measures: How much coefficients vary across different resamples of the training data. Ridge dramatically reduces this variance.

For each coefficient j Stabilityj = 1 − ( SD(β̂j) / |mean(β̂j)| )

SD computed across B bootstrap samples.
Interpretation: Stability close to 1 = rock solid. Lower values suggest the coefficient is unreliable (typical for OLS on collinear data).

5.3 Model Quality & Robustness KPIs

Cross-Validation Score Robustness

K-Fold CV Score CV = (1/K) · Σk=1K Metrick

Standard deviation (stability) σCV = √[ (1/K) · Σk ( Metrick − CV )² ]
Interpretation: Ridge is typically evaluated via 5-fold or 10-fold CV. The CV score determines the optimal λ.

Train–Test Gap (Overfitting Indicator) Robustness

Formula Gap = Metrictest − Metrictrain

For R²: Gap = R²train − R²test
Rule of thumb:
• Gap < 5% → healthy
• Gap 5–10% → mild overfitting, increase λ
• Gap > 10% → serious overfitting, increase λ or reduce features

Residual Diagnostics Robustness

What it measures: Whether the linear-model assumptions hold. Check with plots:

  • Residuals vs. Fitted — should show random scatter around 0. A funnel shape = heteroscedasticity. A curve = non-linearity.
  • QQ Plot — should lie on a straight 45° line. Deviations = non-normal residuals.
  • Residuals vs. Order — patterns indicate autocorrelation (check Durbin-Watson).
  • Residuals vs. Each Feature — patterns suggest the model needs polynomial or interaction terms.

VIF (Variance Inflation Factor) Multicollinearity

What it measures: How much a coefficient's variance is inflated by collinearity with other features. Ridge mitigates but doesn't eliminate VIF.

Formula VIFj = 1 / (1 − R²j)

R²j = R² from regressing feature j on all other features.
Interpretation:
• VIF = 1 → no correlation
• VIF 1–5 → moderate, usually fine
• VIF 5–10 → concerning
• VIF > 10 → severe multicollinearity

AIC / BIC for Ridge Model Selection

What it measures: Model fit penalised by effective degrees of freedom. Useful for comparing Ridge models with different λ.

AIC AIC = 2·df(λ) − 2·ℓ̂ + constant

BIC BIC = ln(N)·df(λ) − 2·ℓ̂ + constant

df(λ) = effective degrees of freedom = trace( X(XᵀX + λI)−1Xᵀ )
Interpretation: Lower AIC/BIC is better. Useful for selecting λ without cross-validation (though CV is preferred).

6 Post-Deployment KPIs — Detailed with Formulas

Once the model is live, you're no longer asking "is it accurate?" — you're asking "is it still accurate today, and is anything silently breaking?"

6.1 Data & Model Health KPIs

PSI (Population Stability Index) Data Drift

Formula PSI = Σi=1B ( Actual%i − Expected%i ) · ln( Actual%i / Expected%i )

B = number of bins (usually 10 deciles)
Expected%i = % of training samples in bin i
Actual%i = % of production samples in bin i
Interpretation thresholds:
• PSI < 0.10 → no significant change, model is stable ✅
• 0.10 ≤ PSI < 0.25 → moderate shift, monitor closely ⚠️
• PSI ≥ 0.25 → major shift, retrain the model 🚨

KS Statistic (Kolmogorov–Smirnov) Data Drift

Formula KS = maxx | Ftrain(x) − Fprod(x) |

F(x) = empirical cumulative distribution function
Interpretation: Range 0 to 1. Higher = more drift. A p-value < 0.05 from the KS test indicates statistically significant drift.

KL Divergence (Kullback–Leibler) Data Drift

Formula DKL(P ‖ Q) = Σi P(i) · log( P(i) / Q(i) )

P = production distribution  |  Q = training distribution
Interpretation: 0 = identical distributions. Higher = more drift. Not symmetric.

Concept Drift (Performance Decay) Model Health

Formula Drift Magnitude = Metricvalidation − Metriclive

Relative decay Decay % = ( Metricvalidation − Metriclive ) / Metricvalidation × 100
Interpretation: Decay > 10% typically triggers a retraining investigation.

Prediction Distribution Shift Model Health

Formula PSIpred = Σ ( ProdPred%i − TrainPred%i ) · ln( ProdPred%i / TrainPred%i )
Interpretation: A sudden jump in predicted values signals a pipeline problem or concept drift.

Coefficient Stability Model Health

Stability Index Stability = 1 − ( || βtrain − βprod || / || βtrain || )
Interpretation: Stability close to 1 = stable. Values below 0.8 suggest the relationship has shifted.

Missing Value Rate Model Health

Formula Missing % = ( Missing values / Total values ) × 100
Interpretation: Ridge cannot handle missing values natively, so a spike in missingness directly degrades predictions.

6.2 Live Performance KPIs

Live RMSE / MAE / R² Performance

Same formulas as pre-deployment Live RMSE = √[ (1/Nlive) · Σ ( ylive − ŷlive )² ]
Live R² = 1 − SSres,live / SStot,live
Interpretation: Ground truth often arrives with a delay. Set up automated pipelines to compute these as soon as labels arrive.

Actual vs. Predicted Monitoring Performance

Formula Deltat = Metricpredicted,t − Metricactual,t

CUSUM (cumulative sum control chart) CUSUMt = max(0, CUSUMt−1 + Deltat − k)
Interpretation: A steadily rising CUSUM indicates systematic drift.

Model Age / Time Since Retrain Performance

Formula Model Age = Current Date − Last Retrain Date
Interpretation: Many teams set a hard limit (e.g. 90 days) as a retraining trigger.

Latency Percentiles (p50, p95, p99) Operational

Definition p95 = the latency value below which 95% of requests fall
Target example: Ridge is extremely fast. p50 < 1 ms, p95 < 5 ms, p99 < 20 ms is typical.

7 Mathematical Formulas — How Ridge Regression Actually Works

The core idea: minimise the sum of squared errors subject to a penalty on the sum of squared coefficients. Here are the formulas.

7.1 The Ridge Cost Function

Ridge minimises the OLS error plus an L2 penalty.

Cost function J(β) = Σi=1N ( yi − β0 − Σj=1p βjxij )² + λ · Σj=1p βj²

Matrix form J(β) = (y − Xβ)ᵀ (y − Xβ) + λ · βᵀβ

Note The intercept β0 is not penalised. Only slope coefficients β₁…βₚ.

7.2 The Closed-Form Solution

Setting the gradient to zero gives the Ridge estimator.

Gradient ∂J/∂β = −2·Xᵀ(y − Xβ) + 2λβ

Setting to zero XᵀXβ + λβ = Xᵀy

Ridge estimator β̂Ridge = ( XᵀX + λI )−1 Xᵀy

Key insight Adding λI guarantees the matrix is invertible even when XᵀX is singular (rank-deficient).

7.3 Ridge as Constrained Optimisation

Ridge can equivalently be stated as minimising SSE subject to a bound on the coefficient norm.

Constrained form minimise   Σi=1N ( yi − ŷi )²
subject to   Σj=1p βj² ≤ t

Lagrangian L(β, λ) = Σ ( yi − ŷi )² + λ ( Σ βj² − t )

Relationship There is a one-to-one mapping between λ and t. Larger λ ↔ smaller t ↔ more shrinkage.

7.4 Ridge via Singular Value Decomposition (SVD)

This form reveals why Ridge works so well numerically.

SVD of X X = U Σ Vᵀ    (Σ is diagonal of singular values σj)

Ridge solution in SVD form β̂Ridge = V · diag( σj / (σj² + λ) ) · Uᵀ y

OLS solution β̂OLS = V · diag( 1 / σj ) · Uᵀ y

Shrinkage factor For each principal direction j:
shrinkagej = σj² / (σj² + λ)

Interpretation Directions with small σj (i.e. collinear directions) get shrunk the most.
Directions with large σj (strong signal) are barely affected.
This is why Ridge stabilises collinear problems — it dampens the unstable directions.

7.5 Gradient Descent Update

Gradient ∂J/∂βj = −2 · Σi xij( yi − ŷi ) + 2λβj

Update rule βj ← βj − α · ∂J/∂βj

Interpretation The gradient has an extra term (2λβj) that pulls coefficients toward zero. Even without data (all residuals = 0), the penalty alone will shrink coefficients.

7.6 Ridge as Bayesian MAP Estimation

Ridge has a clean Bayesian interpretation: it's the maximum a posteriori estimate under a Gaussian prior.

Prior on coefficients βj ~ N( 0, σ²/λ )   (independent Gaussian priors)

Likelihood y | X, β ~ N( Xβ, σ²I )

MAP estimate β̂MAP = argmaxβ [ log P(y | X, β) + log P(β) ]
         = argminβ [ ||y − Xβ||² + λ||β||² ]

Interpretation Ridge assumes a prior belief that coefficients are small and centred on zero.
The larger λ, the stronger the prior, the more the estimates shrink.

7.7 Effective Degrees of Freedom

Hat matrix H(λ) = X (XᵀX + λI)−1 Xᵀ

Effective degrees of freedom df(λ) = trace( H(λ) ) = Σj σj² / (σj² + λ)

Bounds 0 ≤ df(λ) ≤ p
At λ = 0: df = p (OLS)
At λ → ∞: df → 0

7.8 Bias–Variance Decomposition

The theoretical reason Ridge improves test error.

Expected test error E[ (ynew − ŷnew)² ] = Bias² + Variance + σ²noise

OLS bias-variance Bias² = 0   (unbiased)
Variance = σ² · trace( (XᵀX)−1 )

Ridge bias-variance Bias²(λ) = λ² · βᵀ (XᵀX + λI)−2 β
Variance(λ) = σ² · trace( X(XᵀX + λI)−2 Xᵀ )

Trade-off As λ increases: Bias² ↑, Variance ↓.
Optimal λ minimises the total.

7.9 Standardisation Requirement

The penalty Σβj² is not scale-invariant. Without standardisation, features with large scales get unfairly penalised.

Standardisation formula zij = ( xij − x̄j ) / sj

x̄j = mean of feature j
sj = standard deviation of feature j

Then fit Ridge on Z β̂Ridge = (ZᵀZ + λI)−1 Zᵀy

Convert back to original scale βoriginal = βstandardised / sj
β0 = ȳ − Σ βoriginal,j · x̄j

7.10 Kernel Ridge Regression (Nonlinear Extension)

Ridge can be extended to nonlinear models via the kernel trick.

Dual formulation α̂ = ( K + λI )−1 y

Prediction ŷ(x) = Σi αi K(x, xi)

Common kernels Linear: K(x, x') = xᵀx'
RBF (Gaussian): K(x, x') = exp( −||x − x'||² / (2σ²) )
Polynomial: K(x, x') = ( xᵀx' + c )d

Ridge shrinks each principal direction of X by a factor of σj²/(σj² + λ). Directions with small singular values (weak signal, often collinear noise) get shrunk the most. Directions with large singular values (strong signal) are barely affected.

8 Glossary of Acronyms & Terms

Algorithm & Model Concepts

ML

Linear regression with both L1 and L2 penalties combined.

Another name for Ridge Regression, common in numerical linear algebra.
Weight Decay
The neural-network name for L2 regularisation.
KRR
Kernel Ridge Regression — nonlinear Ridge via the kernel trick.
GLM
Generalised Linear Model — extends linear regression to non-Gaussian targets.
Bayesian Ridge
A Bayesian treatment where λ is learned from data with a prior.
ARD
Automatic Relevance Determination — a Bayesian extension that gives each feature its own λ.

Coefficients & Math

β
Coefficient vector — the weights learned by the model.
β̂ (Beta-hat)
The estimated coefficients.
β₀
Intercept — the predicted y when all features are zero. Not penalised in Ridge.
λ (Lambda)
The Ridge regularisation strength. Also called α (alpha) in some libraries.
α (alpha)
In scikit-learn's Ridge, this is the same as λ. Confusingly, in Elastic Net, α is the overall strength and ρ controls the L1/L2 mix.
L2 Norm
||β||₂ = √(Σβⱼ²). The Euclidean length of the coefficient vector.
||β||₂²
Squared L2 norm = Σβⱼ². This is what Ridge penalises.
SVD
Singular Value Decomposition — X = UΣVᵀ. Reveals why Ridge shrinks collinear directions.
σⱼ (sigma-j)
Singular values of X.
Condition Number
Ratio of largest to smallest singular value. Large = unstable inversion.
Effective df
Effective degrees of freedom = trace(H(λ)). Ridge's true complexity.
MAP
Maximum A Posteriori — Bayesian point estimate. Ridge is the MAP under Gaussian priors.
Prior
A Bayesian probability distribution representing belief before seeing data.

Regression Metrics

MAE
Mean Absolute Error — average of |actual − predicted|.
MSE
Mean Squared Error — average of (actual − predicted)². Also the loss Ridge minimises.
RMSE
Root Mean Squared Error — √MSE. Same units as the target.
R²
Coefficient of Determination — proportion of variance explained.
Adjusted R²
R² penalised for the number of features.
MAPE
Mean Absolute Percentage Error — average error as a percentage.
SMAPE
Symmetric MAPE — bounded version of MAPE.
MSLE
Mean Squared Logarithmic Error — squared error on the log scale.
AIC
Akaike Information Criterion — fit penalised by complexity.
BIC
Bayesian Information Criterion — like AIC but penalises complexity more.
CV
Cross-Validation — evaluating on held-out folds.
GCV
Generalised Cross-Validation — a fast approximation used to select λ for Ridge and smoothing splines.

Data & Training Concepts

Feature
An input variable used by the model.
Target
The output variable the model is trying to predict.
Design Matrix
The matrix X of shape (N, p+1) containing all features plus a column of 1s for the intercept.
Standardisation
Rescaling features to mean 0 and standard deviation 1. Required for Ridge.
Centering
Subtracting the mean from each feature so it has mean 0.
Multicollinearity
When predictor features are highly correlated with each other.
VIF
Variance Inflation Factor — measures multicollinearity.
Ill-posed problem
A problem with no unique solution (e.g. OLS when p > N). Ridge makes it well-posed.
Ill-conditioned
A matrix that's nearly singular — inversion amplifies errors. Ridge improves conditioning.
Overfitting
When a model fits training data too well and performs poorly on new data.
Underfitting
When a model is too simple to capture the pattern.
Bias
Systematic error from overly simplistic assumptions. Ridge introduces bias by design.
Variance
Error from sensitivity to training data fluctuations. Ridge reduces variance.
Bias–Variance Tradeoff
The central trade-off Ridge navigates via λ.
Shrinkage
Pulling coefficients toward zero. Ridge's core mechanism.
Regularisation
Penalising complexity to prevent overfitting.
Bootstrap
Resampling with replacement to estimate variance.
K-Fold
Cross-validation with K folds.
Hyperparameter
A setting you choose before training (e.g. λ).
Grid Search
Exhaustively trying each λ from a grid.
Bayesian Optimisation
Smart hyperparameter search using a probabilistic model.
1-SE Rule
Choose the largest λ within 1 SE of the CV minimum. Produces more shrinkage.

Running a new model alongside the old one without acting on its output.

Final tip: Ridge is almost always a good starting point for linear modelling. Tune λ via cross-validation, always standardise your features first, and if you need sparsity, switch to Lasso or Elastic Net. For nonlinear patterns, wrap Ridge in a kernel (Kernel Ridge Regression). For count data or binary targets, use Ridge-regularised GLMs.
