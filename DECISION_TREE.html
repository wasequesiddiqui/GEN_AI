1 Algorithm Description

Real-life analogy: Imagine you're a doctor diagnosing a patient. You don't ask every possible question at once. You ask the most informative question first — "Do you have a fever?" If yes, you ask "Is it above 102°F?" If no, you move to a different branch. That chain of yes/no questions is a decision tree.

What is a Decision Tree?

A Decision Tree is a supervised machine-learning algorithm that predicts a target value by repeatedly splitting the data into smaller and smaller groups based on simple if/else questions about the input features.

It is drawn as an upside-down tree:

  • Root Node — the very first question asked (the best splitting feature).
  • Internal / Decision Nodes — intermediate questions that split data further.
  • Branches — the answers (outcomes) of a question, e.g. "Yes" / "No".
  • Leaf / Terminal Node — the final prediction (a class label or a numeric value). No further splitting happens here.
  • Depth — the number of questions along the longest path from root to leaf.

How the Algorithm Builds the Tree (Step by Step)

Step 1 — Start with all the data at the root

Every row of your training dataset sits at the root node. The tree is currently a single leaf.

Step 2 — Evaluate every possible split

For each feature and each possible threshold/value, the algorithm asks: "If I split the data here, how much purer do the resulting groups become?"

Step 3 — Pick the best split

The split that produces the greatest reduction in impurity (highest Information Gain, or lowest Gini) wins and becomes a decision node.

Step 4 — Recurse

Repeat Steps 2–3 on each child node using only the data that reached it. Each subtree is built independently.

Step 5 — Stop

Recursion stops when one of these conditions is met:

  • All samples in a node belong to the same class (node is pure).
  • No features are left to split on.
  • A stopping rule is triggered — max depth reached, min samples per leaf reached, or improvement is below a threshold.

Step 6 — Prune (optional but recommended)

Grow the tree fully, then cut back branches that add complexity without real predictive value. This fights overfitting.

Two Flavours of Decision Tree

2 Applications

Decision trees are everywhere because they are interpretable, fast, and work on messy tabular data. They also power the strongest ensemble models (Random Forest, XGBoost, LightGBM).

🏦 Banking & Finance

  • Credit scoring — approve/decline a loan based on income, debt ratio, history.
  • Loan default prediction — flag high-risk borrowers.
  • Fraud detection — spot unusual transaction patterns in real time.
  • Anti-money-laundering — classify suspicious activity.

🏥 Healthcare

  • Disease diagnosis — triage patients from symptoms & lab results.
  • Readmission risk — predict who may return within 30 days.
  • Drug response — recommend treatment based on patient profile.
  • Insurance claims — auto-approve low-risk claims.

🛒 Retail & Marketing

  • Customer churn — predict who is about to leave.
  • Customer segmentation — group buyers by behaviour.
  • Product recommendation — decide what to show next.
  • Demand forecasting — regression trees for inventory planning.

🏭 Manufacturing & Operations

  • Predictive maintenance — predict machine failure before it happens.
  • Quality control — classify defective vs. good units.
  • Supply chain risk — flag delayed shipments.
  • Energy load prediction — regression trees on sensor data.

🌐 Technology & Telecom

  • Spam filtering — classic email classification.
  • Network intrusion detection — flag malicious traffic.
  • Customer support routing — send tickets to the right team.
  • App/website personalisation — decide which layout to serve.

🚗 Transport & Others

  • Accident severity prediction — road safety analytics.
  • Flight delay prediction — airline operations.
  • Agriculture — crop yield and disease classification.
  • HR analytics — predict employee attrition.
Why so popular in industry? Because a business analyst can literally read the tree and explain it to a regulator, a doctor, or a CEO. Very few ML models offer that.

3 Advantages

  • Highly interpretable ("white-box") — you can trace exactly why a prediction was made by following the path from root to leaf.
  • No feature scaling required — you don't need to standardise or normalise your data.
  • Handles mixed data types — numeric, categorical, and binary features in one model.
  • Captures non-linear relationships — models complex interactions naturally.
  • Robust to outliers — a single extreme value rarely changes a split threshold much.
  • Handles missing values reasonably — many implementations route missing values down a default branch.
  • Fast to train and predict — prediction is O(depth), extremely quick.
  • Automatic feature selection — unused features are effectively discarded.
  • Great for feature engineering insights — tells you which features matter most.
  • Foundation for ensembles — Random Forest, XGBoost and LightGBM are all built on decision trees.
  • Non-parametric — no distributional assumptions.

4 Disadvantages

  • Severe overfitting — a fully grown tree can memorise training data and fail on new data.
  • High variance / instability — small data changes can completely change the tree structure.
  • Biased toward features with more levels — Information Gain favours high-cardinality features.
  • Greedy, not globally optimal — picks the best split right now, never backtracks.
  • Axis-aligned splits only — struggles with diagonal or rotated decision boundaries.
  • Poor at smooth / linear relationships — regression trees produce jagged step functions.
  • Unstable probability estimates — leaf probabilities can be extreme and poorly calibrated.
  • Cannot extrapolate — regression trees can never predict outside the training range.
  • Not great for high-dimensional sparse data — text or image data usually favours other models.
  • Class imbalance problems — tend to ignore the minority class without correction.
The overfitting trap: Think of a student who memorises the exact answers to last year's exam. They score 100% on the practice paper but fail the real exam because the questions changed. That's a fully grown decision tree.

5 Pre-Deployment KPIs — Detailed with Formulas

These are measured before the model goes live, using a held-out test set or cross-validation. They answer: "Is this model good enough to ship?"

5.1 Confusion Matrix — The Foundation

Almost every classification metric is derived from four numbers. Before formulas make sense, you must understand these four cells.

CellNameMeaning in plain English
TPTrue PositiveThe model said positive, and the truth was positive. ✅ A correct hit.
TNTrue NegativeThe model said negative, and the truth was negative. ✅ A correct rejection.
FPFalse PositiveThe model said positive, but the truth was negative. ❌ A "false alarm" (Type I error).
FNFalse NegativeThe model said negative, but the truth was positive. ❌ A "miss" (Type II error).
Convention: In medical testing, "positive" means "disease present". In fraud detection, "positive" means "this transaction is fraudulent". Always ask: "What does 'positive' mean in this problem?"
Confusion Matrix — Visual Layout
Rows = actual truth. Columns = what the model predicted. The diagonal (TP, TN) is where the model is correct.

5.2 Classification KPIs — Detailed

Accuracy Classification

What it measures: The overall fraction of predictions that were correct — both positives and negatives.

Formula Accuracy = (TP + TN) / (TP + TN + FP + FN)
Worked example: TP = 480, TN = 850, FP = 50, FN = 120
Accuracy = (480 + 850) / (480 + 850 + 50 + 120) = 1330 / 1500 = 0.887 → 88.7%
Interpretation: 88.7% of all predictions were correct. Range: 0 to 1 (higher is better).
✔ Use when Classes are balanced and every correct prediction has equal business value.
✘ Avoid when Classes are imbalanced. A model that always says "legitimate" scores 99% accuracy but catches zero fraud.

Precision (Positive Predictive Value) Classification

What it measures: Of everything the model flagged as positive, how many actually were positive?

Formula Precision = TP / (TP + FP)
Worked example: TP = 480, FP = 50
Precision = 480 / (480 + 50) = 480 / 530 = 0.906 → 90.6%
Interpretation: When the model says "positive", it's right 90.6% of the time. High precision = few false alarms.
✔ Use when False positives are expensive — spam filters, product recommendations, targeted ads.
✘ Avoid when Missing a real positive is far worse than a false alarm (e.g. cancer screening).

Recall / Sensitivity / True Positive Rate Classification

What it measures: Of all the actual positives, how many did the model correctly catch?

Formula Recall = TP / (TP + FN)
Worked example: TP = 480, FN = 120
Recall = 480 / (480 + 120) = 480 / 600 = 0.800 → 80.0%
Interpretation: The model catches 80% of all real positives. It misses 20%. High recall = few missed cases.
✔ Use when Missing a positive is costly — fraud detection, disease screening, safety systems.
✘ Avoid when False alarms cause serious harm (e.g. flagging innocent customers).

Specificity / True Negative Rate Classification

What it measures: Of all the actual negatives, how many did the model correctly identify?

Formula Specificity = TN / (TN + FP)
Worked example: TN = 850, FP = 50
Specificity = 850 / (850 + 50) = 850 / 900 = 0.944 → 94.4%
Interpretation: The model correctly clears 94.4% of the actual negatives. It wrongly flags 5.6% as positive.

Relationship: Specificity + False Positive Rate (FPR) = 1. So FPR = 1 − Specificity = FP / (FP + TN).

F1-Score Classification

What it measures: A single number that balances Precision and Recall. It's the harmonic mean — so it punishes extreme imbalance between them.

Formula F1 = 2 × (Precision × Recall) / (Precision + Recall)

Equivalent form F1 = 2·TP / (2·TP + FP + FN)
Worked example: Precision = 0.906, Recall = 0.800
F1 = 2 × (0.906 × 0.800) / (0.906 + 0.800) = 1.4496 / 1.706 = 0.850
Interpretation: Range 0 to 1. A high F1 means the model is good at both finding positives and not crying wolf.
✔ Use when Classes are imbalanced and you care about both precision and recall roughly equally.
✘ Avoid when Precision and recall have very different business costs — use a weighted F-beta score.

F-beta generalisation: Fβ = (1+β²)·(P·R) / (β²·P + R). β > 1 weights recall higher; β < 1 weights precision higher.

ROC-AUC (Area Under the ROC Curve) Classification

What it measures: The probability that the model ranks a random positive example higher than a random negative example. It evaluates the model across all possible thresholds.

ROC Curve x-axis: FPR = FP / (FP + TN) = 1 − Specificity
y-axis: TPR = TP / (TP + FN) = Recall

AUC (via trapezoidal rule) AUC = Σi ½ · (xi+1 − xi) · (yi+1 + yi)

Probabilistic interpretation (Mann–Whitney U) AUC = P( score(positive) > score(negative) )
Interpretation scale:
• 0.50 → no better than random guessing
• 0.70–0.80 → acceptable
• 0.80–0.90 → excellent
• 0.90–1.00 → outstanding (be suspicious of data leakage)
• Below 0.50 → the model is systematically wrong (flip its predictions!)
✔ Use when You want a threshold-independent measure and classes are reasonably balanced.
✘ Avoid when The positive class is extremely rare — use PR-AUC instead.

PR-AUC (Precision–Recall Area Under the Curve) Classification

What it measures: Area under the Precision–Recall curve. It focuses only on the positive class, making it far more informative when positives are rare.

PR Curve x-axis: Recall = TP / (TP + FN)
y-axis: Precision = TP / (TP + FP)

PR-AUC PR-AUC = ∫ Precision d(Recall)  (approximated by trapezoids)

Baseline Baseline PR-AUC = prevalence = (TP + FN) / (TP + TN + FP + FN)
Example: In a fraud dataset with 1% fraud, a random classifier gets PR-AUC ≈ 0.01 (not 0.5). So a PR-AUC of 0.45 is actually very strong!
✔ Use when The positive class is rare — fraud, disease, defects, intrusions.
✘ Avoid when Both classes matter equally; ROC-AUC is more general.

Log Loss (Binary Cross-Entropy) Classification

What it measures: How well the model's predicted probabilities match reality. It punishes confident wrong predictions very heavily.

Formula (binary) LogLoss = −(1/N) · Σi=1N [ yi·log(pi) + (1−yi)·log(1−pi) ]

yi ∈ {0,1} = actual label  |  pi = predicted probability of class 1

Multi-class extension LogLoss = −(1/N) · Σi Σk yi,k · log(pi,k)
Worked example (N=2):
• Sample 1: actual = 1, predicted prob = 0.9 → loss = −log(0.9) = 0.105
• Sample 2: actual = 0, predicted prob = 0.8 → loss = −log(0.2) = 1.609
LogLoss = (0.105 + 1.609) / 2 = 0.857
Interpretation: Range 0 to ∞ (lower is better). Perfect predictions → 0. A model that always predicts 0.5 gets LogLoss ≈ 0.693 (binary).
✔ Use when You need well-calibrated probabilities — risk scoring, insurance pricing, medical estimates.
✘ Avoid when You only care about the hard class label, not the probability.

Matthews Correlation Coefficient (MCC) Classification

What it measures: A balanced metric that uses all four confusion-matrix cells. It behaves like a correlation coefficient between predictions and truth.

Formula MCC = (TP·TN − FP·FN) / √[ (TP+FP)(TP+FN)(TN+FP)(TN+FN) ]
Worked example: TP=480, TN=850, FP=50, FN=120
Numerator = (480×850) − (50×120) = 408,000 − 6,000 = 402,000
Denominator = √(530 × 600 × 900 × 1000) ≈ 535,000
MCC = 402,000 / 535,000 = 0.751
Interpretation: Range −1 to +1. +1 = perfect, 0 = random, −1 = total disagreement.
✔ Use when Classes are very imbalanced and you want a single trustworthy number.
✘ Avoid when Explaining to a non-technical audience — harder to interpret.

Cohen's Kappa (κ) Classification

What it measures: Agreement between predictions and truth, corrected for agreement that would happen by chance.

Formula κ = (po − pe) / (1 − pe)

po = observed accuracy = (TP + TN) / N
pe = expected chance accuracy = [ (TP+FP)(TP+FN) + (TN+FP)(TN+FN) ] / N²
Landis & Koch scale:
• < 0.00 → poor · 0.00–0.20 → slight · 0.21–0.40 → fair
• 0.41–0.60 → moderate · 0.61–0.80 → substantial · 0.81–1.00 → almost perfect

Balanced Accuracy Classification

What it measures: The average of Recall (on positives) and Specificity (on negatives) — each class contributes equally regardless of size.

Formula Balanced Accuracy = (Recall + Specificity) / 2

= ½ · [ TP/(TP+FN) + TN/(TN+FP) ]
Worked example: Recall = 0.800, Specificity = 0.944
Balanced Accuracy = (0.800 + 0.944) / 2 = 0.872
✔ Use when Classes are imbalanced but you want a simple, class-balanced accuracy.

5.3 Regression KPIs — Detailed

For regression trees (predicting a continuous number), classification metrics don't apply. These are the equivalents.

MAE (Mean Absolute Error) Regression

What it measures: The average size of the prediction error, in the same units as the target.

Formula MAE = (1/N) · Σi=1N | yi − ŷi |

yi = actual value  |  ŷi = predicted value  |  N = number of samples
Worked example: Actual = [100, 200, 300], Predicted = [110, 190, 320]
Errors = |−10|, |10|, |−20| = 10, 10, 20
MAE = (10 + 10 + 20) / 3 = 13.33
Interpretation: On average the prediction is off by 13.33 units. Easy to explain to stakeholders.
✔ Use when You want an easy-to-explain metric and all errors have equal importance.
✘ Avoid when Large errors are dramatically worse than small ones (use RMSE).

MSE (Mean Squared Error) Regression

What it measures: The average of squared errors. Squaring heavily penalises large mistakes.

Formula MSE = (1/N) · Σi=1N ( yi − ŷi )²
Worked example: Errors = [−10, 10, −20]
MSE = (100 + 100 + 400) / 3 = 200
Interpretation: MSE is in squared units (₹², °C²) so it's hard to interpret directly. It's mostly used as a loss function during training.

RMSE (Root Mean Squared Error) Regression

What it measures: The square root of MSE, bringing the metric back to the original units of the target.

Formula RMSE = √[ (1/N) · Σi=1N ( yi − ŷi )² ]
Worked example: MSE = 200
RMSE = √200 = 14.14
Interpretation: On average the model is off by 14.14 units, but large errors are penalised more than in MAE. RMSE ≥ MAE always.
✔ Use when Large errors are genuinely worse (e.g. financial forecasting).
✘ Avoid when The target has outliers you don't care about — use MAE.

R² (Coefficient of Determination) Regression

What it measures: The proportion of the target's variance that the model explains. Compares against the naive "always predict the mean" baseline.

Formula R² = 1 − ( SSres / SStot )

SSres = Σ ( yi − ŷi )²   (residual sum of squares)
SStot = Σ ( yi − ȳ )²   (total sum of squares)
ȳ = mean of the actual values
Worked example: y = [100, 200, 300], ŷ = [110, 190, 320], ȳ = 200
SSres = 100 + 100 + 400 = 600
SStot = 10,000 + 0 + 10,000 = 20,000
R² = 1 − (600 / 20,000) = 0.97
Interpretation: R² = 1 → perfect; R² = 0 → no better than predicting the mean; R² < 0 → worse than the mean (very bad).

Adjusted R² Regression

What it measures: R² adjusted for the number of predictors, penalising models that add features without adding real explanatory power.

Formula Adjusted R² = 1 − [ (1 − R²) · (N − 1) ] / (N − k − 1)

N = number of samples  |  k = number of predictors

Note: for decision trees, "number of predictors" is loosely defined (it's really the tree's complexity), so Adjusted R² is more commonly used for linear models.

MAPE (Mean Absolute Percentage Error) Regression

What it measures: The average error expressed as a percentage of the actual value. Very intuitive for business reporting.

Formula MAPE = (100% / N) · Σi=1N | ( yi − ŷi ) / yi |
Worked example: y = [100, 200, 300], ŷ = [110, 190, 320]
Errors % = |−10/100|, |10/200|, |−20/300| = 0.10, 0.05, 0.0667
MAPE = (0.10 + 0.05 + 0.0667) / 3 × 100 = 7.22%
Interpretation: On average, predictions are off by 7.22%. Range 0% to ∞ (lower is better).
✔ Use when Reporting to business stakeholders and actual values are well above zero.
✘ Avoid when Actual values can be zero or near-zero — MAPE explodes to infinity.

SMAPE (Symmetric Mean Absolute Percentage Error) Regression

What it measures: A symmetric version of MAPE that keeps errors bounded between 0% and 200%.

Formula SMAPE = (100% / N) · Σi=1N | yi − ŷi | / [ (|yi| + |ŷi|) / 2 ]
Interpretation: Range 0% to 200% (lower is better). Handles zero values better than MAPE.

MSLE (Mean Squared Logarithmic Error) Regression

What it measures: Squared error on the log scale. Penalises under-prediction more than over-prediction.

Formula MSLE = (1/N) · Σi=1N ( log(1 + yi) − log(1 + ŷi) )²
✔ Use when The target spans several orders of magnitude (e.g. revenue, population counts).

5.4 Model Quality & Robustness KPIs

Cross-Validation Score Robustness

What it measures: The average performance across K different train/test splits. Gives a more reliable estimate than a single split.

K-Fold CV Score CV = (1/K) · Σk=1K Metrick

Standard deviation (stability) σCV = √[ (1/K) · Σk ( Metrick − CV )² ]
Interpretation: High mean + low standard deviation = trustworthy model. High mean + high SD = unstable, may not generalise.

Train–Test Gap (Overfitting Indicator) Robustness

What it measures: How much better the model performs on training data than on unseen test data.

Formula Gap = Metrictrain − Metrictest

For error metrics (MAE, RMSE, LogLoss): Gap = Metrictest − Metrictrain
Rule of thumb:
• Gap < 5% → healthy
• Gap 5–10% → mild overfitting, consider pruning
• Gap > 10% → serious overfitting, must reduce depth or add regularisation

Tree Depth & Number of Leaves Robustness

What it measures: The structural complexity of the tree. More depth and leaves = more capacity to memorise training noise.

Complexity indicators Depth = max levels from root to any leaf
Leaves = number of terminal nodes
Nodes = total internal + leaf nodes

Rule of thumb for healthy depth max_depth ≈ log₂(N)   (N = number of training samples)
Interpretation: If depth ≫ log₂(N), the tree is likely memorising. If depth ≪ log₂(N), it may be underfitting.

6 Post-Deployment KPIs — Detailed with Formulas

Once the model is live, the questions change. You're no longer asking "is it accurate?" — you're asking "is it still accurate today, and is anything silently breaking?"

6.1 Data & Model Health KPIs

PSI (Population Stability Index) Data Drift

What it measures: How much the distribution of a single feature (or the model's scores) has shifted between training and production.

Formula PSI = Σi=1B ( Actual%i − Expected%i ) · ln( Actual%i / Expected%i )

B = number of bins (usually 10 deciles)
Expected%i = % of training samples in bin i
Actual%i = % of production samples in bin i
Interpretation thresholds:
• PSI < 0.10 → no significant change, model is stable ✅
• 0.10 ≤ PSI < 0.25 → moderate shift, monitor closely ⚠️
• PSI ≥ 0.25 → major shift, retrain the model 🚨

KS Statistic (Kolmogorov–Smirnov) Data Drift

What it measures: The maximum vertical distance between two cumulative distribution functions (training vs. production).

Formula KS = maxx | Ftrain(x) − Fprod(x) |

F(x) = empirical cumulative distribution function
Interpretation: Range 0 to 1. Higher = more drift. A p-value < 0.05 from the KS test indicates statistically significant drift.

KL Divergence (Kullback–Leibler) Data Drift

What it measures: How much one probability distribution diverges from another (asymmetric).

Formula DKL(P ‖ Q) = Σi P(i) · log( P(i) / Q(i) )

P = production distribution  |  Q = training distribution
Interpretation: 0 = identical distributions. Higher = more drift. Not symmetric: DKL(P‖Q) ≠ DKL(Q‖P).

Concept Drift (Performance Decay) Model Health

What it measures: How much the model's live performance has degraded vs. its validation performance.

Formula Drift Magnitude = Metricvalidation − Metriclive

Relative decay Decay % = ( Metricvalidation − Metriclive ) / Metricvalidation × 100
Interpretation: Decay > 10% typically triggers a retraining investigation.

Prediction Distribution Shift Model Health

What it measures: Whether the model's own output distribution has changed over time.

Formula PSIpred = Σ ( ProdPred%i − TrainPred%i ) · ln( ProdPred%i / TrainPred%i )
Interpretation: A sudden jump (e.g. predicting "churn" for 60% of users instead of 8%) signals a problem in the data pipeline or the model itself.

Feature Importance Stability Model Health

What it measures: Whether the same features are still driving decisions over time.

Stability Index Stability = 1 − ( Σ | Imptrain(f) − Impprod(f) | / 2 )

Imp(f) = normalised feature importance of feature f
Interpretation: Stability close to 1 = stable. A sudden reshuffle hints at data pipeline problems or drift.

Missing Value Rate Model Health

What it measures: The percentage of null/empty inputs arriving in production.

Formula Missing % = ( Missing values / Total values ) × 100
Interpretation: A spike usually means an upstream pipeline broke. Even a small increase can degrade tree performance if the tree wasn't trained to handle missing values.

6.2 Live Performance KPIs

Live Accuracy / Precision / Recall Performance

What it measures: The same classification metrics, but recomputed on labelled production data as ground truth arrives.

Same formulas as pre-deployment Live Accuracy = (TPlive + TNlive) / Nlive
Live Precision = TPlive / (TPlive + FPlive)
Live Recall = TPlive / (TPlive + FNlive)
Interpretation: Ground truth often arrives with a delay (days or weeks), so live metrics lag behind reality. Set up automated pipelines to compute them as soon as labels arrive.

Actual vs. Predicted Monitoring Performance

What it measures: Continuous tracking of the delta between what the model said and what actually happened.

Formula Deltat = Metricpredicted,t − Metricactual,t

CUSUM (cumulative sum control chart) CUSUMt = max(0, CUSUMt−1 + Deltat − k)
Interpretation: A steadily rising CUSUM indicates systematic drift. Alert when CUSUM crosses a threshold h.

Model Age / Time Since Retrain Performance

What it measures: How long since the last retraining.

Formula Model Age = Current Date − Last Retrain Date
Interpretation: Many teams set a hard limit (e.g. 90 days) as a retraining trigger, regardless of measured drift.

Latency Percentiles (p50, p95, p99) Operational

What it measures: The time taken to return a prediction, measured at different points in the distribution.

Definition p95 = the latency value below which 95% of requests fall

Why not use the average? Average latency hides tail problems. A few very slow requests (p99) can ruin user experience even if the average looks fine.
Target example: p50 < 20 ms, p95 < 50 ms, p99 < 100 ms for real-time APIs.

6.3 Operational & Business KPIs

Throughput Operational

What it measures: How many predictions the model service handles per unit time.

Formula Throughput = Total predictions served / Time window

Utilisation Utilisation % = (Actual throughput / Peak capacity) × 100
Interpretation: Throughput must exceed peak traffic. Utilisation > 80% is risky — no headroom for bursts.

Error Rate / Failure Rate Operational

What it measures: The percentage of prediction requests that fail (timeouts, exceptions, bad inputs).

Formula Error Rate % = ( Failed requests / Total requests ) × 100
Interpretation: Should be near zero. A sudden spike usually means an upstream data pipeline broke or the model service is overloaded.

Uptime / Availability Operational

What it measures: The percentage of time the model endpoint is reachable.

Formula Uptime % = ( Total time − Downtime ) / Total time × 100%

Common targets 99%  → 3.65 days downtime/year
99.9%  → 8.77 hours downtime/year
99.99% → 52.6 minutes downtime/year

Business Impact KPI Business

What it measures: The metric the business actually cares about — revenue uplift, cost saved, fraud prevented, churn reduced, conversion rate.

Example formulas Revenue Uplift = Revenuewith model − Revenuewithout model
Cost Saved = ( Errorswithout − Errorswith ) × Cost per error
Churn Reduction % = ( Churnbaseline − Churnmodel ) / Churnbaseline × 100

ROI (Return on Investment) Business

What it measures: Whether the value the model generates exceeds the cost of building and running it.

Formula ROI % = ( Net Gain / Total Cost ) × 100%

Net Gain = Business Value Generated − Total Cost
Total Cost = Development + Infrastructure + Maintenance + Monitoring
Worked example: Fraud prevented = ₹5,00,000. Total cost = ₹1,00,000.
Net Gain = ₹4,00,000. ROI = (4,00,000 / 1,00,000) × 100 = 400%

Human Override Rate Business

What it measures: How often a human disagrees with and overrides the model's recommendation.

Formula Override Rate % = ( Overrides / Total decisions ) × 100
Interpretation: A high override rate (e.g. > 30%) means users don't trust the model — investigate feature explanations, UI, or model bias.

Alert / Incident Count Governance

What it measures: Number of monitoring alerts triggered per week. A rising trend signals the model needs attention.

Formula Alert Rate = Alerts triggered / Time period
Golden rule: A model is not "done" when it's deployed. It's done when it's retired. Post-deployment monitoring is what keeps it from silently degrading.

7 Mathematical Formulas — How the Model Actually Works

The core idea is simple: choose the split that makes the resulting groups as "pure" as possible. "Purity" is measured by an impurity function. Here are the ones that matter.

7.1 Entropy (used by ID3 and C4.5)

Entropy measures the disorder or uncertainty in a node. If a node contains only one class, entropy = 0 (perfectly pure). If classes are 50/50, entropy is at its maximum (1 for binary).

Shannon Entropy H(S) = − Σi=1c pi · log2(pi)
SymbolMeaning
SThe set of samples at the current node
cNumber of distinct classes
piProportion of samples in S that belong to class i
log2Base-2 logarithm (so entropy is measured in bits)

Worked example — the classic 9/5 tennis set

Suppose a node has 14 samples: 9 "Play" and 5 "No Play".

p(Play) = 9/14 = 0.643   |   p(No) = 5/14 = 0.357

H(S) = −(0.643 × log₂0.643) − (0.357 × log₂0.357)
     = −(0.643 × (−0.637)) − (0.357 × (−1.485))
     = 0.410 + 0.530 = 0.940 bits

7.2 Gini Impurity (used by CART)

Gini measures the probability of misclassifying a randomly chosen sample if you labelled it according to the node's class distribution. It's slightly cheaper to compute than entropy (no logarithm) and usually gives similar trees.

Gini Impurity Gini(S) = 1 − Σi=1c pi2

For the same 9/5 example:

Gini(S) = 1 − (0.643² + 0.357²) = 1 − (0.413 + 0.127) = 0.460

7.3 Misclassification Error

The simplest impurity measure, but it is not used for growing trees because it is not smooth — it gives zero gradient in many places. It's only useful for pruning.

Misclassification Error Error(S) = 1 − maxi(pi)

7.4 Information Gain — the split criterion

Information Gain is the reduction in entropy achieved by splitting on a feature A. The algorithm picks the feature with the highest gain.

Information Gain IG(S, A) = H(S) − Σv ∈ Values(A) ( |Sv| / |S| ) · H(Sv)
SymbolMeaning
IG(S, A)Information gain from splitting set S on feature A
H(S)Entropy of the parent node before the split
Values(A)All possible values/branches of feature A
SvSubset of S where feature A takes value v
|Sv| / |S|Weight of that branch (proportion of samples going down it)

Worked example — Outlook split

Parent entropy H(S) = 0.940 bits

Outlook = Sunny  → 5 samples (2 Play, 3 No) → H = 0.971
Outlook = Overcast → 4 samples (4 Play, 0 No) → H = 0.000
Outlook = Rain    → 5 samples (3 Play, 2 No) → H = 0.971

Weighted child entropy = (5/14)(0.971) + (4/14)(0.000) + (5/14)(0.971)
                        = 0.347 + 0.000 + 0.347 = 0.694

IG(S, Outlook) = 0.940 − 0.694 = 0.246 bits

7.5 Gain Ratio (used by C4.5)

Information Gain is biased toward features with many distinct values. Gain Ratio fixes this by dividing by the "intrinsic information" of the feature.

Split Information SplitInfo(S, A) = − Σv ( |Sv| / |S| ) · log2( |Sv| / |S| )

Gain Ratio GainRatio(S, A) = IG(S, A) / SplitInfo(S, A)

7.6 Regression Trees — Variance Reduction / MSE

For regression, "impurity" is replaced by the variance of the target values. The best split is the one that most reduces the weighted variance of the children.

Mean Squared Error at a node MSE(S) = (1/|S|) · Σi ∈ S ( yi − ȳS )²

where ȳS = (1/|S|) · Σi ∈ S yi  (the mean target in node S)
Variance Reduction (the regression "Information Gain") VR(S, A) = MSE(S) − Σv ( |Sv| / |S| ) · MSE(Sv)

The leaf prediction for a regression tree is simply the mean of the target values of the training samples that land in that leaf:

Leaf prediction ŷleaf = (1/|Sleaf|) · Σi ∈ Sleaf yi

7.7 Leaf Class Probability (Classification)

For a classification tree, the leaf's predicted probability for class k is the fraction of training samples of class k in that leaf:

Leaf class probability P(class = k | leaf) = ( count of class-k samples in leaf ) / ( total samples in leaf )

Final prediction ŷ = argmaxk P(class = k | leaf)

7.8 Cost-Complexity Pruning (CART)

After growing a full tree T, CART prunes it by minimising a penalised error. α controls the trade-off between accuracy and simplicity.

Cost-Complexity Criterion Rα(T) = R(T) + α · |T̃|

R(T) = misclassification error of tree T
|T̃| = number of terminal (leaf) nodes
α ≥ 0 = complexity penalty (larger α → smaller tree)

You choose α by cross-validation; scikit-learn exposes this as the ccp_alpha parameter.

7.9 Feature Importance

A tree's importance for feature f is the total weighted impurity decrease contributed by all splits on that feature, normalised to sum to 1.

Gini Importance Importance(f) = Σnodes t splitting on f ( Nt / N ) · ΔImpurityt

then normalise: Importance(f) ← Importance(f) / Σf' Importance(f')

8 Glossary of Acronyms & Terms

Every abbreviation used in this study guide, explained in plain English.

Algorithms & Model Types

ML
Machine Learning — a field of AI where systems learn patterns from data instead of being explicitly programmed.
DT
Decision Tree — a model that predicts by asking a series of if/else questions about the features.
CART
Classification And Regression Trees — the algorithm behind scikit-learn's DecisionTreeClassifier and DecisionTreeRegressor. Uses Gini (classification) or MSE (regression) and only binary splits.
ID3
Iterative Dichotomiser 3 — an early tree algorithm by Ross Quinlan that uses Information Gain and only handles categorical features.
C4.5
Successor to ID3 — uses Gain Ratio, handles numeric features and missing values, and performs pruning.
C5.0
Commercial successor to C4.5 — faster, more memory-efficient, supports boosting.
CHAID
Chi-square Automatic Interaction Detector — uses chi-square tests to decide splits; allows multi-way splits.
RF
Random Forest — an ensemble of many decision trees trained on random subsets, then averaged/voted.
XGBoost
Extreme Gradient Boosting — a powerful ensemble of trees built sequentially, each correcting the previous one's errors.
GBM
Gradient Boosting Machine — a general framework for boosting weak learners (usually trees).

Impurity & Splitting

IG
Information Gain — the reduction in entropy after a split. Higher is better.
Entropy
A measure of disorder/uncertainty in a node, measured in bits. 0 = pure, 1 = maximum disorder (binary case).
Gini
Gini Impurity — probability of misclassifying a random sample. 0 = pure.
SplitInfo
Split Information — the intrinsic entropy of the way a feature divides the data. Used in Gain Ratio.
Gain Ratio
Information Gain ÷ Split Information — corrects IG's bias toward high-cardinality features.
Chi-square
A statistical test measuring whether observed frequencies differ from expected. Used by CHAID to pick splits.
Variance Reduction
The regression-tree equivalent of Information Gain — how much the target's variance drops after a split.
Pruning
Cutting back branches of a fully grown tree to reduce overfitting.
Pre-pruning
Stopping tree growth early (e.g. max depth, min samples per leaf). Also called early stopping.
Post-pruning
Growing the tree fully and then trimming it back. Also called backward pruning.
ccp_alpha
Cost-Complexity Pruning alpha — the penalty parameter in scikit-learn's pruning. Larger = simpler tree.
max_depth
The maximum number of levels allowed in the tree. A key hyperparameter for controlling overfitting.
min_samples_leaf
The minimum number of samples that must end up in a leaf. Prevents tiny, overfitted leaves.
min_samples_split
The minimum number of samples a node must have before it can be split.

Evaluation Metrics — Classification

TP
True Positive — model predicted positive, actual was positive. ✅
TN
True Negative — model predicted negative, actual was negative. ✅
FP
False Positive — model predicted positive, actual was negative. Also called a Type I error or "false alarm". ❌
FN
False Negative — model predicted negative, actual was positive. Also called a Type II error or "miss". ❌
Accuracy
(TP + TN) / (TP + TN + FP + FN) — overall correctness.
Precision
TP / (TP + FP) — of the positives predicted, how many were right.
Recall
TP / (TP + FN) — of the actual positives, how many were found. Also called Sensitivity or True Positive Rate.
Specificity
TN / (TN + FP) — of the actual negatives, how many were correctly identified. Also called True Negative Rate.
F1
F1-Score — harmonic mean of Precision and Recall: 2·(P·R)/(P+R).
ROC
Receiver Operating Characteristic — a curve plotting True Positive Rate vs. False Positive Rate across all thresholds.
AUC
Area Under the Curve — the area under the ROC curve. 0.5 = random, 1.0 = perfect.
FPR
False Positive Rate — FP / (FP + TN). The x-axis of the ROC curve.
TPR
True Positive Rate — same as Recall. The y-axis of the ROC curve.
PR-AUC
Precision–Recall Area Under the Curve — better than ROC-AUC for heavily imbalanced datasets.
Log Loss
Logarithmic Loss / Cross-Entropy — penalises confident wrong probability predictions.
MCC
Matthews Correlation Coefficient — a balanced metric ranging from −1 to +1, robust to class imbalance.
Cohen's Kappa
A metric measuring agreement between predictions and truth, corrected for chance.

Evaluation Metrics — Regression

MAE
Mean Absolute Error — average of |actual − predicted|. Same units as the target.
MSE
Mean Squared Error — average of (actual − predicted)². Punishes large errors heavily.
RMSE
Root Mean Squared Error — the square root of MSE. Same units as the target.
MAPE
Mean Absolute Percentage Error — average error expressed as a percentage.
SMAPE
Symmetric Mean Absolute Percentage Error — bounded version of MAPE (0–200%).
MSLE
Mean Squared Logarithmic Error — squared error on the log scale; good for wide-ranging targets.
R²
Coefficient of Determination — proportion of target variance explained by the model. 1 = perfect, 0 = no better than the mean.
Adjusted R²
R² penalised for the number of predictors. Useful when comparing models of different complexity.

Monitoring & Deployment

KPI
Key Performance Indicator — a measurable value used to track how well a model or business process is performing.
PSI
Population Stability Index — measures how much a variable's distribution has shifted between training and production.
KS Test
Kolmogorov–Smirnov Test — a statistical test for whether two distributions differ.
KL Divergence
Kullback–Leibler Divergence — measures how one probability distribution diverges from another.
CSI
Characteristic Stability Index — the per-feature version of PSI.
Data Drift
A change in the distribution of input features over time.
Concept Drift
A change in the relationship between features and the target over time.
CUSUM
Cumulative Sum Control Chart — a sequential analysis technique for monitoring change detection.
MLOps
Machine Learning Operations — the practice of deploying, monitoring and maintaining ML models in production.
CI/CD
Continuous Integration / Continuous Deployment — automated pipelines that test and ship code/model changes.
p50/p95/p99
Percentile latency — p95 = 95% of requests are faster than this value. Better than averages for spotting tail latency.
Uptime
The percentage of time a service is available and responding.
ROI
Return On Investment — (gain from investment − cost) ÷ cost.
Shadow Deployment
Running a new model alongside the old one without acting on its output, to compare performance safely.
A/B Test
Splitting live traffic between two model versions to measure which performs better.
Champion/Challenger
The current production model (champion) vs. a candidate model (challenger) being evaluated.

Data & Training Concepts

Feature
An input variable used by the model (also called a predictor, attribute, or column).
Target
The output variable the model is trying to predict (also called label, response, or y).
Label
The ground-truth value for a training example.
Overfitting
When a model learns the training data too well — including its noise — and performs poorly on new data.
Underfitting
When a model is too simple to capture the underlying pattern, performing poorly on both training and test data.
Bias
Error from overly simplistic assumptions. High bias = underfitting.
Variance
Error from sensitivity to small fluctuations in training data. High variance = overfitting.
Bias–Variance Tradeoff
The balance between a model that is too simple (biased) and one that is too complex (high variance).
Cross-Validation
Splitting data into K folds and training K times, each time holding out a different fold, to get a robust performance estimate.
K-Fold
The specific cross-validation scheme using K folds (commonly K = 5 or 10).
Hyperparameter
A setting you choose before training (e.g. max_depth), as opposed to a parameter the model learns.
Grid Search
Exhaustively trying every combination of hyperparameters to find the best set.
Random Search
Randomly sampling hyperparameter combinations — often faster than grid search.
Train/Test Split
Dividing data into a portion for training and a portion for evaluation.
Hold-out Set
A portion of data never used during training, reserved for final evaluation.
Class Imbalance
When one class has far fewer samples than another, which can bias the model.
Resampling
Adjusting class balance via oversampling, undersampling, or SMOTE.
SMOTE
Synthetic Minority Over-sampling Technique — generates synthetic examples of the minority class.
Feature Engineering
Creating new, more informative features from existing ones.
One-Hot Encoding
Converting a categorical variable into multiple binary columns.
Ordinal Encoding
Mapping categories to integers that preserve order.
Normalisation
Rescaling features to a 0–1 range. (Not needed for decision trees!)
Standardisation
Rescaling features to mean 0 and standard deviation 1. (Not needed for decision trees!)

Explainability

XAI
Explainable AI — methods and tools that make model decisions understandable to humans.
SHAP
SHapley Additive exPlanations — a game-theory-based method that assigns each feature a contribution to a prediction.
LIME
Local Interpretable Model-agnostic Explanations — explains individual predictions by fitting a simple local model around them.
Feature Importance
A score showing how much each feature contributed to the model's decisions.
PDP
Partial Dependence Plot — shows the marginal effect of one feature on the predicted outcome.
ICE Plot
Individual Conditional Expectation Plot — like a PDP but one line per sample, revealing heterogeneity.
White-box
A model whose internals are directly interpretable (e.g. a decision tree or linear regression).
Black-box
A model whose internals are opaque (e.g. a deep neural network).
