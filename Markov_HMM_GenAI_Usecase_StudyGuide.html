Overview

Markov Models and Hidden Markov Models (HMMs) are foundational probabilistic sequence models that underpin many generative AI techniques. They model systems that transition between states over time, making them ideal for generating and analysing sequential data — from text to speech to biological sequences.

What Is a Markov Model?

A Markov chain is a stochastic model describing a sequence of possible events where the probability of each event depends only on the state attained in the previous event — the Markov property (memoryless property). In Gen AI, this allows efficient next-step prediction without storing the entire history.

What Is a Hidden Markov Model (HMM)?

An HMM extends Markov chains by introducing hidden (latent) states that emit observable outputs. The true state sequence is not directly visible; we only see the emissions. HMMs are doubly stochastic: one process governs state transitions, another governs observation emissions. This makes them powerful for modelling generative processes where the underlying structure is latent — exactly the paradigm of generative AI.

Worked Example: Weather Prediction → Text Generation

From Weather to Words

Consider a simple 2-state Markov chain for weather: Sunny (S) and Rainy (R).

Transition matrix:

  • P(S → S) = 0.8, P(S → R) = 0.2
  • P(R → S) = 0.4, P(R → R) = 0.6

Given today is Sunny, the probability of the sequence [S, S, R] = 1.0 × 0.8 × 0.2 = 0.16.

This same principle scales to text generation: train a Markov model on a corpus, learn P(wordₜ | wordₜ₋₁, …, wordₜ₋ₖ), and sample new sentences by walking the chain. Modern LLMs extend this with neural embeddings and attention, but the autoregressive sampling principle remains the same.

Glossary — Key Terms

Markov PropertyFuture state depends only on the present state, not on the sequence of past states.
Transition ProbabilityProbability of moving from state i to state j: aᵢⱼ = P(qₜ₊₁ = j | qₜ = i).
Emission ProbabilityProbability of observing output oₖ given hidden state j: bⱼ(oₖ) = P(oₖ | qₜ = j).
Stationary DistributionThe long-run probability distribution over states, π = π·A, reached after many transitions.
Baum–Welch AlgorithmAn EM algorithm for learning HMM parameters (A, B, π) from unlabelled observation sequences.
Viterbi AlgorithmDynamic programming to find the most likely hidden state sequence given observations.
Forward–BackwardComputes P(O|λ) and posterior state probabilities efficiently via DP.
Autoregressive GenerationGenerating tokens one at a time, each conditioned on previous outputs — a Markov-like process.

Pipeline / Process

Click each step to expand detailed content. This pipeline shows how Markov/HMM models are used in a typical Gen AI sequence-generation workflow.

Data Preparation & State Definition

Define the state space and observation space. For text generation, states might be POS tags (hidden) and words (observed). For music, states could be chords and observations the notes.

  • Tokenise / discretise raw data into a finite vocabulary
  • Define k (order of Markov assumption) — higher k captures more context but increases parameters exponentially
  • For HMMs, decide the number of hidden states N and observation symbols M
Parameter Initialisation

Initialise the HMM parameters λ = (A, B, π):

  • A — N×N transition matrix (random or uniform)
  • B — N×M emission matrix (random or uniform)
  • π — initial state distribution (size N)

For simple Markov chains, only the k-th order transition counts need to be initialised.

Training / Parameter Estimation

Supervised: Count transitions and emissions directly from labelled data (MLE).
Unsupervised (HMM): Use the Baum–Welch algorithm (EM):

  • E-step: Compute expected state occupancies and transition counts via forward-backward
  • M-step: Update A, B, π to maximise expected log-likelihood
  • Iterate until convergence
Inference / Decoding

Given trained parameters λ, answer key questions:

  • Evaluation: P(O|λ) — compute likelihood of an observation sequence (forward algorithm)
  • Decoding: Find most likely hidden state sequence Q* = argmax P(Q|O,λ) (Viterbi algorithm)
  • Filtering/Smoothing: P(qₜ | o₁…oₜ) or P(qₜ | o₁…oₜ) via forward-backward posteriors
Sequence Generation (Sampling)

Generate new sequences by sampling from the learned model:

  • Markov chain: Start from initial state ~ π, then repeatedly sample next state: qₜ₊₁ ~ A[qₜ, :]
  • HMM: First sample hidden state sequence, then sample emissions: oₜ ~ B[qₜ, :]
  • LLM connection: Modern LLMs do this at massive scale — sample tokenₜ₊₁ ~ softmax(f(token₁…tokenₜ))
Evaluation & Refinement

Assess generated quality:

  • Perplexity: exp(−1/T Σ log P(oₜ|context)) — lower is better
  • Log-likelihood on held-out data for model selection
  • Compare multiple HMM topologies (varying N, k) using AIC/BIC
  • Human evaluation for creative generation tasks

Worked Example: Music Melody Generation with HMM

Generating a Simple Melody

States = {C-major, G-major, A-minor, F-major} (4 hidden chord states).
Observations = {C4, D4, E4, F4, G4, A4, B4, C5} (8 possible melody notes).

After training on Mozart excerpts:

  1. Sample initial chord ~ π → "C-major"
  2. Emit note ~ B["C-major", :] → "E4" (with high probability, since E is in C-major)
  3. Transition chord ~ A["C-major", :] → "G-major"
  4. Emit next note → "D4" … and so on

The result is a harmonically coherent melody that sounds "Mozart-like" — an early form of generative music AI.

Connection to Generative AI

The transition matrix is the generative engine. In modern LLMs, this matrix is not stored explicitly — it's computed dynamically via a neural network (the transformer). But the principle is identical:

  1. Given current state (context), compute a probability distribution over next states (tokens)
  2. Sample from that distribution
  3. Feed the new state back as input
  4. Repeat → autoregressive generation

When you prompt ChatGPT and it generates one word at a time, it's performing a highly sophisticated Markov-like walk through token space!

Worked Example: Next-Token Sampling in an LLM

From HMM to GPT

Consider the prompt: "The cat sat on the"

HMM approach: States = grammatical roles (determiner, noun, verb, preposition). Transition matrix learned from corpus. Most likely next state after "the" (determiner) → noun. Sample a noun emission → "mat" (with high probability).

LLM approach: Context window → transformer → logits over 50k+ vocabulary → softmax → sample "mat" (P ≈ 0.4), "floor" (P ≈ 0.3), "roof" (P ≈ 0.1), …

Both follow the same sample-from-conditional-distribution paradigm — just at vastly different scales.

Glossary: Core Mechanism Terms

Stochastic MatrixA square matrix where each row sums to 1 — each row is a valid probability distribution over next states.
ErgodicityA Markov chain is ergodic if it's possible to reach any state from any other state (irreducible + aperiodic).
Temperature (τ)Scales logits before softmax: higher τ → more diverse samples; lower τ → more deterministic. Critical for Gen AI output control.
Top-k / Top-p SamplingRestrict sampling to the k most likely tokens or the smallest set with cumulative probability ≥ p. Prevents low-quality outputs.

Architecture

Internal Structure of a Hidden Markov Model

An HMM is defined by the 5-tuple λ = (N, M, A, B, π):

ComponentSymbolDimensionsDescription
Number of hidden statesNScalarHow many distinct latent states the model can be in
Number of observation symbolsMScalarSize of the discrete observation vocabulary
State transition matrixA = {aᵢⱼ}N × Naᵢⱼ = P(qₜ₊₁ = j | qₜ = i), each row sums to 1
Emission matrixB = {bⱼ(k)}N × Mbⱼ(k) = P(oₜ = vₖ | qₜ = j), each row sums to 1
Initial state distributionπ = {πᵢ}1 × Nπᵢ = P(q₁ = i), sums to 1

Three Canonical Problems

Problem 1: Evaluation — P(O | λ)

Given: Observation sequence O and model λ.
Find: Likelihood P(O|λ).
Solution: Forward algorithm — dynamic programming in O(N²T). Avoids the naive O(Nᵀ) by computing αₜ(i) = P(o₁…oₜ, qₜ=i | λ) recursively.

Problem 2: Decoding — Best Hidden State Sequence

Given: Observation sequence O and model λ.
Find: Q* = argmax_Q P(Q | O, λ).
Solution: Viterbi algorithm — similar DP structure but uses max instead of sum. Backtracking recovers the optimal path.

Problem 3: Learning — Estimate λ from Data

Given: Observation sequence(s) O.
Find: λ* = argmax_λ P(O | λ).
Solution: Baum–Welch (EM) — iteratively refines A, B, π using expected sufficient statistics from forward-backward.

How HMM Components Connect

The architecture follows a clean generative story:

  1. π determines the first hidden state q₁
  2. B emits the first observation o₁ from q₁
  3. A transitions to the next hidden state q₂
  4. B emits o₂ from q₂
  5. Repeat for T time steps…

This two-layer stochastic process (hidden → observed) is the blueprint for virtually all modern deep generative models: VAEs have encoder/decoder; diffusion models have forward/reverse process; even GANs have generator/discriminator — all variations on the HMM's idea of latent structure generating observed data.

CGAI Exam Must-Knows

🔑 Core Formulas to Memorise

  • Markov Property: P(qₜ₊₁ | q₁, …, qₜ) = P(qₜ₊₁ | qₜ)
  • Sequence Probability: P(O | λ) = Σ_Q π_{q₁} · b_{q₁}(o₁) · Πₜ₌₂ᵀ a_{qₜ₋₁,qₜ} · b_{qₜ}(oₜ)
  • Forward Recursion: αₜ(j) = [ Σᵢ αₜ₋₁(i) · aᵢⱼ ] · bⱼ(oₜ)
  • Viterbi Recursion: δₜ(j) = maxᵢ [ δₜ₋₁(i) · aᵢⱼ ] · bⱼ(oₜ)
  • Baum–Welch Re-estimation: āᵢⱼ = expected transitions i→j / expected visits to i

📋 Exam-Ready Summary Points

  1. HMMs are doubly stochastic: one process for state transitions (A, π), another for emissions (B)
  2. The three canonical problems (evaluation, decoding, learning) each have classic DP solutions
  3. The forward-backward algorithm computes posterior probabilities P(qₜ=i | O, λ) — used in both evaluation and as the E-step of Baum–Welch
  4. Baum–Welch = EM for HMMs — guaranteed to increase likelihood each iteration but may converge to local optimum
  5. Modern Gen AI (LLMs, diffusion) extends and generalises HMM principles rather than replacing them
  6. The autoregressive generation paradigm (sample one token at a time, feed back) is directly inherited from Markov models

Worked Example: Viterbi Decoding

POS Tagging with Viterbi

Sentence: "Time flies like an arrow"
Hidden states: {Noun, Verb, Preposition, Determiner}
Observations: the 5 words above

Using trained A and B matrices, Viterbi computes:

  1. δ₁(Noun) = π_Noun × B_Noun("Time")
  2. δ₂(Verb) = max(δ₁(Noun)×A_Noun→Verb, δ₁(Verb)×A_Verb→Verb, …) × B_Verb("flies")
  3. Continue for all words…
  4. Backtrack: "Time"(Noun) → "flies"(Verb) → "like"(Prep) → "an"(Det) → "arrow"(Noun)

The Viterbi path reveals the most probable grammatical structure — a classic NLP task that directly inspired neural sequence labelling (BiLSTM-CRF, etc.).

Glossary: Exam Terminology

Latent VariableA variable that is not directly observed but inferred from observed data. In HMMs, the hidden states are latent variables.
Expectation–Maximisation (EM)An iterative optimisation method for models with latent variables. E-step computes expectations; M-step maximises.
Dynamic Programming (DP)Breaking a problem into overlapping subproblems. Forward, backward, and Viterbi all use DP for O(N²T) efficiency.
Log-Likelihoodlog P(O|λ) — used instead of likelihood to avoid numerical underflow in long sequences.
