1 Algorithm Description

Real-life analogy: You want to know the probability that a new bridge will collapse in an earthquake. You can't build 10,000 bridges to test. But you can simulate 10,000 virtual earthquakes, each with random magnitude, location, soil conditions, and structural stress, and count how many times the virtual bridge fails. That's Monte Carlo — replacing an impossible experiment with a giant number of random simulations, and using the law of large numbers to get a reliable answer.

What is Monte Carlo Simulation?

Monte Carlo (MC) simulation is a computational technique that solves deterministic or probabilistic problems by repeated random sampling. Instead of solving an equation analytically, we generate many random scenarios, compute the outcome for each, and aggregate the results. The answer emerges statistically — more samples give a more accurate estimate.

The name comes from the famous casino in Monaco. It's the general-purpose "brute force" of probability — when math is too hard, simulate.

How it Works (Step by Step)

Step 1
Define the problem
Identify the quantity you want to estimate: π, a portfolio's VaR, an option price, the probability of system failure.
Step 2
Model the inputs
Specify probability distributions for all uncertain inputs (normal, uniform, lognormal, empirical, copulas…).
Step 3
Generate random samples
Draw N random samples from each input distribution. Use a pseudo-random generator (Mersenne Twister, PCG, Sobol for quasi-MC).
Step 4
Evaluate the model
For each sample, compute the deterministic outcome. E.g., price an option, evaluate a portfolio, run a physics simulation.
Step 5
Aggregate results
Average, count, or take quantiles of the N outcomes. The sample mean converges to the true expectation as N grows.
Step 6
Estimate error
Compute the standard error of the estimate: SE = σ / √N. Use it to build confidence intervals and decide when to stop.

2 Applications

Monte Carlo is one of the most universally applicable computational techniques — it's used anywhere you need to answer "what happens under uncertainty?" at scale.

💰 Quantitative Finance

  • Option pricing — Black-Scholes is closed-form, but exotic options (Asian, barrier, lookback) are priced by Monte Carlo.
  • Value at Risk (VaR) — simulate 10,000 portfolio scenarios for regulatory risk.
  • Credit portfolio simulation — correlated defaults, CDO pricing.
  • Interest rate derivatives — Hull-White, LIBOR Market Model.
  • Real options — valuation of corporate investment decisions.

🏥 Healthcare & Life Sciences

  • Drug trial simulation — design trials with simulated patients.
  • Epidemic modelling — stochastic SIR/SEIR models.
  • Radiation therapy planning — Monte Carlo dose calculation.
  • Cost-effectiveness analysis — probabilistic health economics.
  • Protein folding — MCMC over conformational space.

🏭 Engineering & Physics

  • Neutron transport — reactor design (MCNP).
  • Reliability analysis — probability of system failure.
  • Structural safety — earthquake / wind load simulation.
  • Molecular dynamics — Monte Carlo sampling of states.
  • Photon transport — medical imaging (PET, SPECT).

📊 Statistics & Machine Learning

  • Bootstrap confidence intervals — resample to quantify uncertainty.
  • Bayesian inference (MCMC) — sample from posteriors.
  • Reinforcement learning — Monte Carlo rollouts, MCTS.
  • Random forest / dropout — internal randomness.
  • Hyperparameter search — random search outperforms grid.

🏗️ Business & Operations

  • Project risk management — simulate timelines.
  • Supply chain optimization — demand and lead-time variability.
  • Inventory policy — safety stock under stochastic demand.
  • Capacity planning — queueing with random arrivals.
  • Real estate development — NPV under uncertain rents.

🎮 Gaming, Graphics & More

  • Path tracing — photorealistic rendering (Pixar, Blender).
  • Physics engines — particle simulations.
  • Game AI — Monte Carlo Tree Search (AlphaGo).
  • Climate models — ensemble forecasting (IPCC).
  • Nuclear physics, cosmology, epidemiology — everywhere.
Why is Monte Carlo so widely used? Because real-world problems are almost always probabilistic, high-dimensional, and analytically intractable. Monte Carlo lets you skip the math and go straight to the answer — with a mathematically guaranteed error rate. It's the most general-purpose numerical algorithm in existence.

3 Advantages

  • Works in any dimension — convergence rate is O(1/√N) regardless of dimension. Numerical quadrature breaks at ~10 dimensions; MC doesn't care.
  • No analytical solution required — you only need to be able to simulate the system, not solve it in closed form.
  • Handles arbitrary input distributions — normal, lognormal, empirical, copulas, mixtures, anything you can sample from.
  • Simple to implement — the basic algorithm is a few lines of code, and parallelism is trivial (each sample is independent).
  • Error is quantifiable — the standard error σ/√N gives a rigorous confidence interval on the estimate.
  • Works on any integrand — no smoothness, differentiability, or structure required. It even works on discontinuous functions.
  • Naturally parallelises — embarrassingly parallel across CPUs, GPUs, and clusters. Rendering farms are Monte Carlo.
  • Variance reduction techniques extend reach — antithetic variates, control variates, importance sampling, common random numbers, stratification — all reduce SE without more samples.
  • Quasi-Monte Carlo (Sobol, Halton) — low-discrepancy sequences push convergence to nearly O(1/N) for smooth integrands.
  • Model-free — you don't need to derive a formula. Real-world complexity is captured in the simulator.
  • Well-understood theory — LLN, CLT, and concentration inequalities give rigorous guarantees.
  • Easy to communicate — output is a histogram of outcomes; stakeholders understand "5% chance of losing more than $1M" intuitively.
  • Foundation for modern ML — MCMC, variational inference, MCTS, and bootstrapping all rest on MC principles.

4 Disadvantages

  • Slow convergence — O(1/√N) is very slow. To halve the error, you need 4× the samples. To get 3-digit precision, you might need millions of runs.
  • Computationally expensive — each sample may require a full simulation (e.g., path-dependent option pricing needs 252 daily steps). 10,000 paths × 252 steps = 2.5M evaluations.
  • Requires good random number generators — bad PRNGs (short periods, correlations) can silently bias results. Use Mersenne Twister, PCG, or a hardware source.
  • Output is only as good as the input model — if your assumed input distribution is wrong, the output is wrong. GIGO — garbage in, garbage out.
  • No closed-form insight — MC gives you the answer, not the "why." Sensitivity to parameters is not directly visible.
  • Reproducibility issues — results differ between runs unless you fix the random seed. Regulatory and scientific contexts often require this.
  • Standard error can mislead — for heavy-tailed distributions, the sample variance may not converge, and the CLT-based error can be wildly optimistic.
  • Rare-event simulation is hard — if the event has probability 1e-6, you need ~1e8 samples to see it once. Requires importance sampling or subset simulation.
  • Memory and storage — storing all 10M sample paths for post-analysis can be prohibitive.
  • Not a substitute for analytical thinking — MC can hide modelling errors. It's easy to get a smooth-looking distribution from a wrong model.
  • Variance estimation for tails is unstable — the 99.9% quantile estimate has much larger error than the mean.
  • Deterministic problems are better solved analytically — don't use MC to compute π when arctan gives the answer instantly.
  • Adaptive/sequential MC requires care — particle filters, MCMC chains, and importance sampling all have their own convergence and mixing issues.
  • Curse of dimensionality in function approximation — while MC integration scales, MC-based function approximation (e.g., value iteration) does not escape the curse.
The slow-convergence trap: If your current MC estimate has 5% error with 10,000 paths and you want 1% error, you don't need 5× more paths — you need 25× more, i.e., 250,000. And for 0.1% error, you need 2.5 million. This quadratic relationship is why variance reduction techniques (antithetic, control variates, importance sampling) are essential in production.

5 Pre-Deployment KPIs — Detailed with Formulas

Before deploying a Monte Carlo estimator, you must verify three things: (1) is it converged? (2) is it accurate? (3) is it efficient? The KPIs below cover all three.

5.1 Convergence KPIs

Standard Error (SE) Accuracy

What it measures: The standard deviation of the sample mean estimator. This is the most fundamental MC error metric.

Formula SE = σ̂ / √N

σ̂ = sample standard deviation of the N simulated outcomes
N = number of samples (paths)

Interpretation The MC estimate is approximately normally distributed around the true value
with standard deviation SE. This is the CLT in action.
Worked example: 10,000 simulated option payoffs have sample SD = $3.50.
SE = 3.50 / √10,000 = 3.50 / 100 = $0.035
Interpretation: Lower is better. Halving SE requires 4× more samples.
✔ Use when You want a single number describing the precision of your MC estimate.
✘ Avoid when The outcome distribution is heavy-tailed — SE can be misleadingly small.

Confidence Interval (CI) Accuracy

What it measures: A range around the MC estimate that contains the true value with a specified probability (typically 95%).

Formula CI95% = x̄ ± 1.96 · SE

Half-width (absolute error) HW = 1.96 · σ̂ / √N

Required N for target half-width ε N = ( 1.96 · σ̂ / ε )²
Worked example: x̄ = $12.40, SE = $0.035.
CI = $12.40 ± $0.069 = [ $12.33, $12.47 ]
To achieve ±$0.01 half-width: N = (1.96 · 3.50 / 0.01)² = 470,596
Interpretation: The CI width is what you report to stakeholders. If it's too wide, increase N or reduce σ via variance reduction.

Relative Error Accuracy

What it measures: The CI half-width as a fraction of the estimate. Scale-free accuracy metric.

Formula RE = HW / |x̄| = ( 1.96 · σ̂ ) / ( √N · |x̄| )

Coefficient of Variation (CV) CV = σ̂ / |x̄|
RE = 1.96 · CV / √N
Interpretation scale:
• RE < 1% → production-ready ✅
• RE 1–5% → acceptable for most applications
• RE > 10% → increase N or use variance reduction

Effective Sample Size (ESS) Convergence

What it measures: For correlated samples (MCMC, sequential MC), the equivalent number of independent samples that would give the same precision.

Formula ESS = N / ( 1 + 2 · Σt=1T ρt )

ρt = autocorrelation at lag t
T = truncation lag (where autocorrelation dies out)
Interpretation: ESS ≪ N means samples are highly correlated and you need more iterations. Only ESS is meaningful; N is misleading.

Gelman-Rubin R̂ (R-hat) Convergence

What it measures: Whether multiple MCMC chains have converged to the same distribution. Compares between-chain and within-chain variance.

Formula R̂ = √[ ( ( N − 1 ) / N · W + B / N ) / W ]

W = within-chain variance (average)
B = between-chain variance × N

Interpretation R̂ ≈ 1.00 → chains have converged
R̂ > 1.01 → not converged, run more iterations

5.2 Accuracy & Validation KPIs

Bias vs. Analytical Solution Validation

What it measures: Whether the MC estimate matches a known analytical truth (for test problems).

Formula Bias = x̄MC − xtrue

Bias as multiples of SE z = ( x̄MC − xtrue ) / SE

|z| < 2 → consistent with unbiased estimate at 95% confidence
Interpretation: For any known-answer problem (e.g., π, Black-Scholes), MC should be within ~2 SE of truth 95% of the time. Persistent bias indicates a bug or a bad model.

Convergence Diagnostic — Geweke Test Convergence

What it measures: Whether the beginning and end of a sample sequence have the same mean (no drift).

Geweke z-score z = ( x̄early − x̄late ) / √( SEearly² + SElate² )

Interpretation |z| < 1.96 → no evidence of non-convergence
|z| > 2 → not converged, run longer

Variance Reduction Ratio (VRR) Efficiency

What it measures: How much a variance reduction technique (antithetic, control variate, importance sampling) reduces the standard error.

Formula VRR = Var( MC naive ) / Var( MC reduced )

Equivalent speedup Speedup = VRR × (time per naive path / time per reduced path)

Interpretation VRR = 16 → reduced estimator needs 16× fewer paths for the same SE
Interpretation: VRR > 4 is worth implementing. VRR > 100 is excellent and usually achievable with control variates on financial derivatives.

5.3 Efficiency KPIs

Paths per Second (Throughput) Performance

What it measures: How many simulated paths (samples) the engine processes per second.

Formula Throughput = N / Trun

N = total paths simulated
Trun = wall-clock runtime (seconds)
Interpretation: Target depends on problem complexity. Simple option pricing on GPU: 10M+ paths/sec. Complex path-dependent: 100K–1M paths/sec. Longstaff-Schwartz regression at each step: 10–100K paths/sec.

Time-to-Precision Performance

What it measures: Runtime required to reach a target standard error.

Formula T = ( σ̂² · τ ) / SE²

τ = average time per path
SE = target standard error
Interpretation: Combine SE and throughput into a single "efficiency" number. Lower is better. Used to compare algorithms, not just hardware.

Random Number Generator Quality Quality

What it measures: The statistical quality of the pseudo-random generator. Test with the Diehard, NIST, or TestU01 suites.

Key properties • Long period (≥ 2128)
• Passes chi-squared uniformity tests
• Passes serial correlation tests
• Passes spectral tests
• No low-order bit correlations
Interpretation: Use well-tested PRNGs: Mersenne Twister, PCG64, Philox, xoshiro256. Never use language defaults without verification.

6 Post-Deployment KPIs — Detailed with Formulas

Once a Monte Carlo model is in production (pricing options, computing VaR, running simulations for real decisions), you must monitor whether the output remains accurate, well-calibrated, and stable.

6.1 Backtesting KPIs

Prediction Interval Coverage Calibration

What it measures: Whether the model's prediction intervals contain the realized outcome at the expected rate.

Formula Coverage = # { t : yt ∈ [ Lt, Ut ] } / T

[Lt, Ut] = 95% prediction interval at time t

Expected coverage For a 95% interval, coverage should be ≈ 0.95
Interpretation: Coverage < 0.90 = intervals too narrow (model underestimates uncertainty). Coverage > 0.98 = intervals too wide (model overestimates uncertainty).

Kupiec POF Test (VaR Backtesting) Backtesting

What it measures: Whether the number of VaR breaches matches the expected breach rate. Standard regulatory test.

Null hypothesis H₀: actual breach rate = expected breach rate (e.g., 5% for 95% VaR)

Likelihood ratio statistic LRPOF = −2 · ln[ ( 1 − p )N−x · px ] + 2 · ln[ ( 1 − x/N )N−x · ( x/N )x ]

p = expected breach probability
x = observed number of breaches
N = number of observations

LR ~ χ²(1) under H₀
Interpretation: p-value < 0.05 → model is mis-calibrated; VaR is too low (too many breaches) or too high (too few breaches).

Christoffersen Independence Test Backtesting

What it measures: Whether VaR breaches are independent over time (no clustering).

Formula LRIND = −2 · ln[ (1−π)n₀₀+n₁₀ · πn₀₁+n₁₁ ] + 2 · ln[ (1−π₀)n₀₀ · π₀n₀₁ · (1−π₁)n₁₀ · π₁n₁₁ ]

nij = number of transitions from state i to state j (0 = no breach, 1 = breach)
π = (n₀₁ + n₁₁) / N, π₀ = n₀₁/(n₀₀+n₀₁), π₁ = n₁₁/(n₁₀+n₁₁)
Interpretation: p-value < 0.05 → breaches cluster; model misses regime changes.

Expected Shortfall (ES) Backtest Backtesting

What it measures: Whether the model's average loss on breach days matches the ES prediction.

Formula ESactual = ( 1 / #breaches ) · Σbreach days losst

Ratio ES ratio = ESactual / ESpredicted

Ratio ≈ 1 → well-calibrated
Interpretation: Ratio > 1.2 → ES underestimated. Ratio < 0.8 → ES overestimated. Basel FRTB mandates ES backtests.

6.2 Model Drift KPIs

Estimate Stability Across Runs Stability

What it measures: Whether the MC estimate is stable when re-run with different random seeds.

Formula Stability = 1 − ( SDacross runs / | meanacross runs | )

Alternative: SE across runs SEcross = SD( x̄run 1, x̄run 2, …, x̄run K )
Should be ≈ SE / √K
Interpretation: Cross-run SE should match within-run SE. If it's much larger, the random number generator or model has an issue.

Parameter Sensitivity Drift Stability

What it measures: How much the MC output changes when inputs shift slightly. Monitors the model's "delta."

Sensitivity Sθ = ( ∂ MC / ∂ θ ) · ( θ / MC )

Numerical estimate (bump-and-revalue) Sθ ≈ [ MC(θ + Δ) − MC(θ) ] / Δ · ( θ / MC(θ) )
Interpretation: A sensitivity that drifts over time suggests the model's response to inputs has changed — investigate before trusting new outputs.

Output Distribution Drift (PSI / KS) Stability

What it measures: Whether the distribution of MC outputs has shifted vs. training time.

Population Stability Index (PSI) PSI = Σi ( A%i − E%i ) · ln( A%i / E%i )

Kolmogorov-Smirnov statistic KS = maxx | Ftrain(x) − Fprod(x) |
PSI thresholds:
• PSI < 0.10 → stable ✅
• 0.10 ≤ PSI < 0.25 → moderate shift ⚠️
• PSI ≥ 0.25 → significant drift, investigate 🚨

Model Version Stability Stability

What it measures: When you upgrade the MC engine (new RNG, new hardware, new algorithm), does the output change more than expected?

Formula Δ = | MCnew − MCold | / SEcombined

SEcombined = √( SEnew² + SEold² )
Interpretation: |Δ| < 2 → new version consistent with old. |Δ| > 3 → investigate before promoting to production.

6.3 Operational KPIs

Latency Percentiles (p50/p95/p99) Operational

What it measures: Time to complete a full MC run.

Formula Latency = wall-clock time from request to result

Track p50, p95, p99 for a rolling window.
Target example: For real-time pricing, p95 < 100 ms. For overnight risk, p95 < 4 hours for the whole book.

Throughput (Paths/sec) Operational

Formula Throughput = # paths completed / second

Scale with resources Ideally scales linearly with CPU/GPU count — parallel efficiency
Speedup(p) = T(1) / T(p)
Efficiency(p) = Speedup(p) / p

Failure & Retry Rate Operational

Formula FailureRate = failed runs / total runs
RetryRate = retried runs / total runs
Interpretation: Should be near zero. Common failures: numerical overflow, singular matrices, out-of-domain samples.

Cost per Simulation Business

What it measures: Total computational cost (CPU-hours × price) per MC run or per estimate.

Formula Cost = ( CPU-hours ) × ( price per CPU-hour ) + GPU costs + storage

Cost per unit precision Cost / SE

Business Impact / ROI Business

Formula ROI % = ( Net Gain / Total Cost ) × 100%

Example (trading) Net Gain = improvement in P&L from better pricing
Cost = infrastructure + development + monitoring
Worked example: Better VaR estimates reduce regulatory capital by ₹50 Cr. Total MC infra cost = ₹5 Cr.
ROI = (50 − 5) / 5 × 100 = 900%
Golden rule: A Monte Carlo model is only as good as its calibration to reality. A beautiful simulation with wrong inputs produces beautiful nonsense. Always backtest against realized outcomes, monitor drift, and re-validate whenever the input distribution changes.

7 Mathematical Formulas — How Monte Carlo Works

The core idea: estimate an expectation by averaging random samples. Everything else is variations on this theme.

7.1 The Fundamental Theorem of Monte Carlo

Goal Compute I = E[ f(X) ] = ∫ f(x) p(x) dx

Monte Carlo estimator ÎN = (1/N) · Σi=1N f( Xi )

where Xi ~ p (i.i.d. samples from the distribution of X)

Law of Large Numbers ÎN → I   almost surely as N → ∞

Central Limit Theorem √N · ( ÎN − I ) / σ   →   N( 0, 1 )   as N → ∞
where σ² = Var[ f(X) ]

7.2 Standard Error and Confidence Interval

Sample variance of f(X) σ̂² = ( 1 / (N − 1) ) · Σi=1N ( f(Xi) − ÎN )²

Standard error SE = σ̂ / √N

95% confidence interval CI = ÎN ± 1.96 · SE

Relative error RE = 1.96 · SE / | ÎN |

7.3 Convergence Rate — The 1/√N Law

Error scaling | ÎN − I | ~ O( σ / √N )

Samples needed to reach target error ε N = ( 1.96 · σ / ε )²

Dimension independence The rate σ/√N is independent of the dimension d of X.
This is why MC beats grid-based quadrature for d ≥ 5.

Compare to quadrature Trapezoidal rule: O( N−2/d )   (curse of dimensionality!)
Monte Carlo: O( N−1/2 )   (dimension-independent)
QMC (Sobol): O( N−1 · log(N)d )   (nearly O(1/N))

7.4 Variance Reduction Techniques

Antithetic Variates If U ~ Uniform(0,1) and Ū = 1 − U, use both:
ÎAT = (1/N) · Σi=1N/2 [ f( Ui ) + f( Ūi ) ]
Variance reduction when Cov( f(U), f(1−U) ) < 0

Control Variates Suppose we know E[ g(X) ] = μg analytically, where g is correlated with f:
ÎCV = ÎN − c · ( ĝN − μg )
with optimal c* = Cov( f, g ) / Var( g )
Variance reduction factor = 1 − ρf,g²

Importance Sampling Sample from a biased distribution q instead of p:
I = Ep[ f(X) ] = Eq[ f(X) · p(X) / q(X) ]
ÎIS = (1/N) · Σi=1N f( Yi ) · w( Yi )
where Yi ~ q, w( y ) = p( y ) / q( y ) is the importance weight
Choose q proportional to |f · p| to get zero variance (ideal case)

Stratified Sampling Split domain into m strata, sample nk from each:
ÎST = Σk=1m pk · Îk
Var( ÎST ) ≤ Var( ÎN ) when strata are homogeneous

Common Random Numbers (CRN) Use the same random seed across scenarios to compare them consistently.
Reduces variance of differences, key for sensitivity analysis.

7.5 Quasi-Monte Carlo (QMC)

Low-discrepancy sequences Instead of i.i.d. uniform, use Sobol, Halton, or Faure sequences
They fill the unit cube more uniformly than random

Koksma-Hlawka inequality | ÎQMC − I | ≤ V( f ) · DN*
DN* = star-discrepancy of the point set
V( f ) = Hardy-Krause variation of f

Convergence rate For Sobol: DN* = O( ( log N )d / N )
QMC achieves nearly O( 1/N ) for smooth integrands

7.6 Monte Carlo for Option Pricing (GBM)

Geometric Brownian Motion dSt = μ St dt + σ St dWt

Closed-form solution St = S0 · exp[ ( μ − σ²/2 ) · t + σ · Wt ]

Discrete simulation (Euler-Maruyama) St+Δt = St · exp[ ( μ − σ²/2 ) · Δt + σ · √Δt · Z ]
where Z ~ N( 0, 1 )

European call option price V = e−rT · E[ max( ST − K, 0 ) ]
ÎMC = e−rT · (1/N) · Σi=1N max( ST(i) − K, 0 )

Black-Scholes closed form (for validation) C = S0 · Φ( d1 ) − K · e−rT · Φ( d2 )
d1 = [ ln( S0 / K ) + ( r + σ²/2 ) · T ] / ( σ · √T )
d2 = d1 − σ · √T

7.7 Value at Risk (VaR) and Expected Shortfall (ES)

VaR at level α VaRα = inf { x : P( L > x ) ≤ 1 − α }
= the α-quantile of the loss distribution

Monte Carlo VaR 1. Simulate N loss scenarios L1, L2, …, LN
2. Sort: L(1) ≤ L(2) ≤ … ≤ L(N)
3. VaRα ≈ L(⌈α·N⌉)

Expected Shortfall (CVaR) ESα = E[ L | L > VaRα ]
ESα ≈ ( 1 / #breach ) · Σi : Li > VaRα Li

Standard error of VaR SE( VaRα ) ≈ √[ α( 1 − α ) / N ] / f( qα )
f( qα ) = density of loss distribution at the α-quantile

7.8 Bootstrap Confidence Intervals

Procedure 1. From the original sample X1, …, XN, draw B bootstrap samples
(each with replacement, same size N)
2. Compute the statistic θ̂b on each bootstrap sample
3. The bootstrap distribution of θ̂ approximates the sampling distribution

Percentile CI CI95% = [ θ̂(0.025), θ̂(0.975) ]

Bias-corrected (BCa) Adjusts for bias and skewness using the jackknife

Bootstrap standard error SEboot = √[ (1/(B−1)) · Σb ( θ̂b − θ̄ )² ]

7.9 Markov Chain Monte Carlo (MCMC)

Metropolis-Hastings 1. Start at θ0
2. Propose θ' ~ q( θ' | θt )
3. Accept with probability:
α = min( 1, [ p(θ') · q(θt | θ') ] / [ p(θt) · q(θ' | θt) ] )
4. θt+1 = θ' if accepted, else θt

Gibbs Sampler Sample each coordinate from its full conditional:
θi ~ p( θi | θ−i, data )

Effective Sample Size ESS = N / ( 1 + 2 · Σt=1T ρt )

7.10 Assumptions of Monte Carlo

I
i.i.d. samples
Samples must be independent and identically distributed

7.11 Central Limit Theorem — The Foundation

Everything in Monte Carlo rests on this one theorem. It's what allows us to put a confidence interval on a simulation.

Statement Let X1, X2, …, XN be i.i.d. with mean μ and variance σ² < ∞.
Then as N → ∞:

√N · ( X̄N − μ ) / σ   →d  N( 0, 1 )

Practical implication For large N, X̄N ≈ N( μ, σ²/N )
So X̄N ± 1.96 · σ/√N is an approximate 95% CI

Berry-Esseen bound | FN(x) − Φ(x) | ≤ C · E[|X−μ|³] / ( σ³ · √N )
Gives a rate for how fast CLT convergence happens

Final tip: Monte Carlo is the most general-purpose numerical technique in existence — but only if used thoughtfully. Always (1) validate against analytical solutions on known test problems, (2) report SE and CI alongside every estimate, (3) use variance reduction when VRR > 4, (4) verify your RNG quality, (5) monitor cross-run stability in production, and (6) backtest against realized outcomes. A Monte Carlo estimate without an error bar is not a result — it's a wish.
