Zero-Shot Learning – Hyperparameters

Master the art of recognizing unseen classes by bridging visual features with semantic embeddings.

Zero-Shot Learning (ZSL) enables models to recognize classes never seen during training by mapping visual features into a semantic embedding space (attributes, word vectors). This guide covers the 10 most important hyperparameters for ZSL, from embedding dimension and compatibility functions to ranking loss and hubness calibration, with practical PyTorch examples and a runnable ZSL demo.

🧬

① Semantic Embedding Dimension

Dimensionality of the class attribute/word vectors. Larger dimensions encode richer semantics but require more training data.

# Common semantic spaces
attr_dim = 85 # AWA: 85 class-level attributes
w2v_dim = 300 # Word2Vec: 300-d word vectors
glove_dim = 300 # GloVe: 300-d embeddings
💡Attributes (30–312 dims) give interpretable ZSL; word vectors (300d) scale to thousands of classes with less annotation effort.
🔬

② Visual Feature Dimension (Backbone)

Output dimension of the CNN backbone used to extract image features. Typically from a pretrained ResNet or ViT.

import torchvision.models as models
backbone = models.resnet101(pretrained=True)
visual_dim = 2048 # ResNet-101 output
✅ResNet-101 (2048d) is standard. ViT-B/16 (768d) and CLIP (512d) are modern alternatives with better generalization.
🔗

③ Joint Embedding / Projection Dimension

Shared dimension for mapping both visual and semantic features. Balances expressiveness and overfitting risk.

self.visual_proj = nn.Linear(2048, joint_dim=512)
self.semantic_proj = nn.Linear(attr_dim, joint_dim=512)
# Cosine similarity in joint space
score = F.cosine_similarity(v_proj, s_proj)
💡Joint dim 256–1024. Smaller dims (256–512) work best for attribute-based ZSL; larger (1024) for word vector spaces.
🎯

④ Compatibility Function

The scoring function between visual features and class semantics. Linear, bilinear, and cosine-based scores are common choices.

# Linear compatibility
score = visual_feat @ W @ semantic_vec
# Bilinear (learned compatibility)
score = visual_feat @ W_pair @ semantic_vec
# Cosine (no learned params)
score = F.cosine_similarity(vis, sem)
✅Bilinear compatibility (learned interaction matrix) is most expressive. Cosine is simpler and handles the hubness problem better.
📉

⑤ Loss Function (Ranking Loss)

ZSL uses ranking-based losses (pairwise or hinge) to push correct class scores above incorrect ones by a margin.

# Hinge ranking loss with margin
loss = max(0, margin - pos_score + neg_score)
# Triplet loss variant
loss = max(0, d(vis, pos_sem) - d(vis, neg_sem) + margin)
💡Margin=0.1–1.0. Pairwise ranking loss is standard. Cross-entropy on seen classes optionally regularizes joint training.
🎯

⑥ Learning Rate

ZSL often fine-tunes a pretrained backbone with a lower LR for the CNN and higher LR for the projection layers.

# Differential learning rates
optimizer = Adam([
{'params': backbone.parameters(), 'lr': 1e-5},
{'params': projection.parameters(), 'lr': 1e-4}])
✅Use 1e-5 for pretrained backbone, 1e-4 to 1e-3 for ZSL-specific layers. Differential LRs prevent distorting pretrained features.
📦

⑦ Batch Size

Batch size for ZSL training. Larger batches provide more negative examples for ranking loss, improving discriminative quality.

# Batch includes images from multiple seen classes
dataloader = DataLoader(
dataset, batch_size=128,
shuffle=True)
💡Batch size 64–256. Larger batches provide richer negative sampling for ranking loss. Use class-balanced sampling.
🔄

⑧ Training Epochs

ZSL models converge quickly (10–50 epochs) with pretrained backbones. Monitor seen-class accuracy and unseen-class harmonic mean.

for epoch in range(30):
train_epoch(model, seen_loader)
# Validate on both seen & unseen
seen_acc = evaluate(model, seen_test)
unseen_acc = evaluate(model, unseen_test)
H = 2*seen_acc*unseen_acc/(seen_acc+unseen_acc)
✅Track harmonic mean H of seen and unseen accuracy. Stop when H plateaus — overfitting reduces unseen performance.
🔧

⑨ Optimizer & Weight Decay

Adam/AdamW with moderate weight decay. ZSL models benefit from stronger regularization on the projection layers.

optimizer = AdamW(
model.parameters(),
lr=1e-4,
weight_decay=1e-4)
scheduler = CosineAnnealingLR(optimizer, T_max=30)
💡Adam with wd=1e-4 to 1e-3. Cosine LR scheduling helps avoid overfitting to seen classes at the expense of unseen generalization.
🌐

⑩ Semantic Space Type

The choice of class representation — attributes, word vectors, or text descriptions. Drastically affects ZSL performance and scalability.

# ① Attribute vectors (AWA/CUB datasets)
semantic = class_attributes # (num_classes, attr_dim)
# ② Word vectors (ImageNet-scale ZSL)
semantic = word2vec[class_names]
# ③ CLIP text embeddings (modern ZSL)
semantic = clip.encode_text(class_descriptions)
✅CLIP-style text embeddings are the state-of-the-art choice. Attributes remain important for fine-grained ZSL (bird species, etc.).

🏗️ Zero-Shot Learning Architecture

ZSL maps visual features and class semantics into a shared space where compatibility scores determine class membership. The architecture has three stages: visual encoding, semantic projection, and compatibility scoring.

🔬 ZSL Core Equations
Visual Embedding:
φ(x) = CNNθ(x)   ∈ ℝdv
Semantic Embedding:
ψ(y) = ay (attributes) or word2vec(y)
Compatibility Score:
s(x,y) = φ(x)T W ψ(y)   (bilinear)
Zero-Shot Prediction:
ŷ = argmaxy∈Yunseen s(x, y)

📖 Equation Element Breakdown – Visual-Semantic Mapping

Each component of the ZSL pipeline explained — from visual feature extraction to zero-shot classification.

🔹 Visual & Semantic Encoding
φ(x)
Visual feature vector extracted from image x via a pretrained CNN (ResNet, ViT, CLIP).
Shape: d_v (e.g., 2048 for ResNet-101)
ψ(y)
Semantic embedding of class y: either hand-crafted attribute vector a_y or learned word embedding.
Shape: d_s (e.g., 85 for AWA attributes, 300 for word2vec)
W (Bilinear)
Learned compatibility matrix mapping visual features to semantic space. Captures cross-modal relationships.
Shape: (d_v × d_s) — high-dimensional but allows rich interactions
Yunseen
Set of class labels never observed during training. The model must infer their semantics from side information alone.
Typically 10–50% of total classes (e.g., 10 unseen out of 50 AWA classes)
🔹 Generalized vs. Classical ZSL
Classical ZSL
Test set contains ONLY unseen classes. Search space is restricted: ŷ = argmax_{y∈Y_unseen} s(x,y).
Optimistic setting — easier to evaluate
Generalized ZSL (GZSL)
Test set contains BOTH seen and unseen classes. ŷ = argmax_{y∈Y_seen ∪ Y_unseen} s(x,y).
Realistic setting — model must not bias toward seen classes
Hubness Problem
In high-dimensional spaces, some classes become "hubs" — nearest to many query points. Biases predictions.
Solved via normalized scores, calibrated stacking, or test-time adaptation
Harmonic Mean (H)
H = 2·S·U/(S+U) where S = seen accuracy, U = unseen accuracy. Balances both in GZSL evaluation.
Single metric capturing the seen-unseen trade-off
🔹 Modern Approaches
CLIP-style ZSL
Uses dual encoders (image + text transformer) pretrained on 400M image-text pairs. Zero-shot via cosine similarity.
No task-specific training needed — purely zero-shot
Generative ZSL
Uses a conditional GAN/VAE to synthesize visual features for unseen classes, then trains a standard classifier.
f-GAN, TF-VAEGAN — bridges ZSL to supervised learning
💡 Key insight: The semantic space is the bridge between seen and unseen classes. Its quality (attribute discrimination, embedding coverage) directly determines ZSL performance — a weak semantic space guarantees poor zero-shot transfer.
🔍

Visual-Semantic Projection

Learns a mapping W: φ(x) ↦ ψ(y) that aligns visual features with class semantics. The learned compatibility enables zero-shot inference.

💡Bilinear models (SJE, LATEM) learn per-class or shared compatibility; ALE and DEVISE use simpler linear projections with ranking loss.
🔄

Transductive ZSL

Uses unlabeled unseen-class images during training (without labels) to adapt the model. Improves GZSL performance substantially.

✅Transductive setting uses test images for domain adaptation. Only the labels of unseen classes are withheld, not the images themselves.

⚡ Training Process for Zero-Shot Learning

ZSL training focuses on learning a transferable visual-semantic mapping that generalizes to unseen classes.

🎯

Ranking Loss Training

Trains the model to rank the correct class above all others. Pairwise ranking with margin is the standard ZSL objective.

def rank_loss(vis, sem, labels):
scores = vis @ W @ sem.T # (batch, num_classes)
pos = scores.gather(1, labels)
loss = (margin - pos + scores).clamp(min=0).sum(1)
return loss.mean()
✅Pairwise ranking loss with margin=0.1–1.0. The margin controls how much higher the correct score must be than incorrect ones.
⚖️

Seen/Unseen Calibration

GZSL requires calibrating prediction scores to avoid bias toward seen classes. Calibrated stacking reduces this bias.

# Calibrated stacking: subtract seen-class bias
seen_bias = gamma * s(x, y_seen)
unseen_scores = s(x, y_unseen) - seen_bias
pred = argmax(cat(seen_scores, unseen_scores))
⚠️Without calibration, GZSL models often classify 90%+ of unseen samples as seen classes. γ=0.2–0.5 is typical.
🔬

Class-Balanced Sampling

Ensures each seen class contributes equally to the batch, preventing dominant classes from skewing the ranking objective.

from torch.utils.data import WeightedRandomSampler
weights = 1.0 / class_counts
sampler = WeightedRandomSampler(weights, num_samples)
💡Balanced sampling is critical — without it, the model learns to rank frequent seen classes higher, degrading unseen-class performance.
📊

Validation on Unseen Proxy

During training, evaluate on held-out seen classes as a proxy for unseen generalization. Track harmonic mean of seen+unseen accuracy.

# Split seen classes into train_seen/val_seen
val_seen = seen_classes[-20%:]
train_seen = seen_classes[:-20%]
# val_seen acts as "unseen" proxy for tuning

🛡️ Regularization & Tuning for ZSL

ZSL is prone to overfitting on seen classes. These techniques improve generalization to unseen classes.

📐

L2 Regularization on W

Regularize the compatibility matrix W to prevent overfitting to seen-class co-occurrence patterns that don't transfer.

# Add L2 penalty to compatibility matrix
l2_reg = weight_decay * (W.norm(2) ** 2)
total_loss = rank_loss + l2_reg
💡Weight decay of 1e-4 to 1e-3 on the projection layers is standard. Stronger L2 (1e-3) helps when seen classes are few.
🔀

Semantic Dropout

Randomly drops semantic dimensions during training, forcing the model to use distributed attribute representations.

self.sem_dropout = nn.Dropout(0.3)
semantic_vec = self.sem_dropout(attributes)
# Forces distributed use of attributes
✅Semantic dropout (0.2–0.5) prevents the model from relying on a few discriminative attributes that may not generalize to unseen classes.
🎯

Hubness Calibration

Mitigates the hubness problem where certain classes dominate nearest-neighbor predictions in high-dimensional embedding spaces.

# Normalize scores to reduce hubness
scores_norm = (scores - scores.mean(0)) / scores.std(0)
# Or use cosine similarity instead of dot product
scores = F.cosine_similarity(vis, sem.unsqueeze(0))
💡Cosine similarity implicitly normalizes and reduces hubness. Z-score normalization across classes is another effective approach.
🧊

Freezing the Backbone

Keep the pretrained CNN backbone frozen and only train the projection layers. Prevents distortion of general visual features.

# Freeze pretrained backbone
for param in backbone.parameters():
param.requires_grad = False
# Only train ZSL projection layers
optimizer = Adam(projection.parameters())
✅Frozen backbone + trainable projection is the simplest effective ZSL strategy. Fine-tuning the backbone can help but risks overfitting.

💻 Full Code – Zero-Shot Learning with Bilinear Compatibility

A complete ZSL training pipeline using ResNet features, attribute embeddings, and bilinear compatibility. All hyperparameters annotated.

#!/usr/bin/env python3 """Zero-Shot Learning with Bilinear Compatibility – all hyperparameters labeled.""" import torch import torch.nn as nn import torch.nn.functional as F import torch.optim as optim import torchvision.models as models # ── Hyperparameters ── VISUAL_DIM = 2048 # ② Visual feature dimension (ResNet-101) ATTR_DIM = 85 # ① Semantic/attribute dimension (AWA dataset) JOINT_DIM = 512 # ③ Joint embedding projection dimension MARGIN = 0.5 # ⑤ Ranking loss margin LR_BACKBONE = 1e-5 # ⑥ Learning rate for pretrained CNN LR_PROJECTION = 1e-4 # ⑥ Learning rate for ZSL projection layers BATCH_SIZE = 128 # ⑦ Batch size EPOCHS = 30 # ⑧ Training epochs WEIGHT_DECAY = 1e-4 # ⑨ Weight decay for optimizer SEM_DROPOUT = 0.3 # Semantic dropout rate class ZSLModel(nn.Module): def __init__(self, num_seen_classes, attributes): super().__init__() # Pretrained visual backbone (frozen) backbone = models.resnet101(pretrained=True) for p in backbone.parameters(): p.requires_grad = False self.visual_encoder = nn.Sequential(*list(backbone.children())[:-1]) self.flatten = nn.Flatten() # ③ Joint embedding projection layers self.visual_proj = nn.Linear(VISUAL_DIM, JOINT_DIM) self.attr_proj = nn.Linear(ATTR_DIM, JOINT_DIM) # ④ Bilinear compatibility matrix: W ∈ R^{d_v × d_s} self.W = nn.Parameter(torch.randn(VISUAL_DIM, ATTR_DIM) * 0.01) # Register class attributes (⑩ semantic space) self.register_buffer('attributes', attributes) # (num_all_classes, ATTR_DIM) self.sem_dropout = nn.Dropout(SEM_DROPOUT) def forward(self, images): # Extract visual features vis_feat = self.flatten(self.visual_encoder(images)) # (batch, 2048) # ④ Bilinear compatibility: s(x,y) = φ(x)ᵀ W ψ(y) semantics = self.sem_dropout(self.attributes) # (num_classes, ATTR_DIM) scores = vis_feat @ self.W @ semantics.T # (batch, num_classes) return scores # ── Dataset & DataLoader ── # attributes: (num_classes, ATTR_DIM) — all classes, seen + unseen # seen_classes: subset of class indices used for training train_loader = DataLoader(seen_dataset, batch_size=BATCH_SIZE, shuffle=True, num_workers=4) model = ZSLModel(num_seen_classes, all_attributes).to(device) # ── ⑥/⑨ Differential learning rates ── optimizer = optim.AdamW([ {'params': model.visual_proj.parameters(), 'lr': LR_PROJECTION}, {'params': model.attr_proj.parameters(), 'lr': LR_PROJECTION}, {'params': [model.W], 'lr': LR_PROJECTION} ], weight_decay=WEIGHT_DECAY) # ── Training loop ── for epoch in range(EPOCHS): model.train() for images, labels in train_loader: images, labels = images.to(device), labels.to(device) scores = model(images) # (batch, num_all_classes) # ⑤ Pairwise ranking loss (only seen classes) pos_scores = scores.gather(1, labels.unsqueeze(1)) seen_scores = scores[:, seen_class_indices] loss = (pos_scores - seen_scores + MARGIN).clamp(min=0) loss = loss.sum(1).mean() optimizer.zero_grad() loss.backward() optimizer.step() # ── GZSL evaluation ── model.eval() with torch.no_grad(): all_scores = model(test_features) seen_acc = accuracy(all_scores[:, seen_idx], seen_labels) unseen_acc = accuracy(all_scores[:, unseen_idx], unseen_labels) H = 2 * seen_acc * unseen_acc / (seen_acc + unseen_acc) print(f"Epoch {epoch+1}/{EPOCHS} | Loss: {loss:.3f} | H: {H:.3f}")

⬆️ Complete ZSL pipeline with bilinear compatibility and pairwise ranking loss. All ⑩ hyperparameters annotated.
